## 集群无 API 单节点验收

先确认集群 Python 能加载运行依赖，并用同一个环境预检 Mock。下列命令不提交作业。

```bash
M="$R/configurations/experiments/r15p5-site-no-api.json"
"$P" -s -B -c 'import sys,numpy,pytz,tqdm; print(sys.version.split()[0], numpy.__version__, pytz.__version__, tqdm.__version__)'
"$P" -s -B "$R/tools/experiment.py" prepare "$M"
"$P" -s -B "$R/tools/experiment.py" status "$M"
```

如果这份配置已有作业或批次计划，沿用原回执。需要新验收且获得确认时，复用现有文件锁探针申请**一台节点上的两个进程**。探针申请 2 核、1 GiB、5 分钟。三种子 Mock 每段申请 2 核、2 GiB、30 分钟，依赖审核每段申请 1 核、1 GiB、5 分钟。Mock 最多 12 段，目标每种子 20 个成功返回，合计请求预留最多 132，真实 API 请求和求解均为零。

```bash
FS_JOB=$(sbatch --parsable --no-requeue --partition=128C_02 --account=wz --qos=normal --nodes=1 --ntasks=2 --ntasks-per-node=2 --cpus-per-task=1 --mem=1024M --time=00:05:00 --chdir="$R" --output="$R/r15-site-lock-%j.out" "$R/tools/experiment_fs_probe.sbatch" "$P") &&
  printf '文件锁作业 %s\n' "${FS_JOB%%;*}"
```

```bash
"$P" -s -B "$R/tools/experiment.py" run "$M" --approve
```

审核作业自动接续，无需手动提交第二段。验收通过需要文件锁作业正常退出、两个进程各留下 `fs-pass` 和 `permit-pass`，三种子都完成 20/20，审核回执覆盖各段作业且至少发生一次自动接续。用以下命令核对终态并导出。

```bash
sacct -n -P -X -j "${FS_JOB%%;*}" --format=JobIDRaw,State,ExitCode
cat "$R/reports/r15-fs-smoke/${FS_JOB%%;*}"/{fs-pass,permit-pass}-{0,1}.json
"$P" -s -B "$R/tools/experiment.py" status "$M"
cat "$R/plans/candidate-lab-r15p5-site-no-api/campaign-control"/review-*.json
"$P" -s -B "$R/tools/experiment.py" export "$M" --out "$HOME/r15p5-site-no-api-results.zip"
```

`outcome=scientific_complete`、`segments` 至少为 2，以及导出包含三个种子，才构成三种子现场完成证据。每个种子的 `exports/summary.json` 应记录 `engineering_only=true`、`confirmed_sends=0`、真实首解和复核启动均为零。旧 `site.py` 的 `site_ready` 额外要求双节点互斥，单节点回执只覆盖单节点部署。

## 真实验收

### API 并发探针

在每次运行前填入已确认的账号 RPM 和 TPM。同一批的 `--name` 保持一致。先 `W=2`，结果 `passed=true` 后才可改为 `W=4`，最后 `W=8`。每档两波，硬上限分别为 4、8、16 次，总计 28 次。任一波出现失败或未知发送、用量异常时停止后续波次；该档不可用于批准升档。

```bash
W=2
"$P" -s -B "$R/tools/r15_acceptance.py" api plan --name line-test-01 --width "$W"
```

有该档授权后，先单独运行下面一行，在提示出现后输入已确认的 RPM 和 TPM，中间用空格分开。

```bash
read -r -p '输入已确认的 RPM 和 TPM，用空格分开：' HDL_RPM HDL_TPM
```

输入完成后，再运行提交命令。

```bash
srun --chdir="$R" -p 128C_02 -A wz --qos=normal -N 1 -n 1 -c "$((W+1))" --mem=2048M -t 00:15:00 \
  "$P" -s -B "$R/tools/r15_acceptance.py" api run --name line-test-01 --width "$W" \
  --rpm "${HDL_RPM:?先填写已确认的 RPM}" --tpm "${HDL_TPM:?先填写已确认的 TPM}" \
  --approve-requests "$((2*W))" --approve-solves 0 --confirm-exclusive-account
```

用 `"$P" -s -B "$R/tools/r15_acceptance.py" api status --name line-test-01 --width "$W"` 查看。结果放在 `reports/acceptance-line-test-01/api-<width>/`，包括逐请求发送时间、确认在途峰值、已知 token、未知用量、HTTP 错误、`Retry-After`、每波与整档耗时。阶段通过需要两波全部成功并实际达到目标峰值。这是有限样本。真实账号能力还需实测。

金额费用以服务商账单和请求标识核对。探针保留已知 token 与未知用量，报表不会从 token 自行估算账单。

## OBP H401

H401 已有 train96、向量 H 生成与验证、R_code 评价，以及训练逐实例最好包络均值贪心筛选。真实操作还需要模型账号已释放、排他期覆盖原窗口和明确的 API/求解授权。原预算是种子 401、40 次生成尝试、每槽最多一次物理发送、最多 7680 次首解和复核。全部 40 槽结算后冻结 10 条有效、AST 不同的规则。若不足 10 条则停止。

账号可独占后准备配置；这一命令只写计划和检查输入。

```bash
"$P" -s -B experiments/triad/six_ops.py obp-h-prepare --exclusive-hours 72 --confirm-exclusive-account
HC=preparations/operations/obp-H401/config.json
HR=runs/obp-H401
"$P" -s -B experiments/triad/assets.py job-submit --asset obp-H --config "$HC" --run-dir "$HR"
```

预算和提交经过用户授权后，执行实际提交命令。以应用状态 `completed` 和 40 个已结算槽位为冻结入口的前提。

```bash
"$P" -s -B experiments/triad/assets.py job-submit --asset obp-H --config "$HC" --run-dir "$HR" \
  --submit --allow-api --approve-budget 40 --allow-solves --approve-solves 7680
"$P" -s -B experiments/triad/entry.py status --kind h-build --config "$HC" --run-dir "$HR"
```

确认作业终态、无写入后，冻结并绑定。固定 H 从同一批已验证的训练成本提取 960 行，自动按训练 J 和冻结顺序选优。以下操作均不新增 API 或求解。

```bash
HF="$PWD/preparations/operations/obp-H401/H_frozen.json"
"$P" -s -B experiments/triad/assets.py freeze --run-dir "$HR" --output "$HF"
"$P" -s -B experiments/triad/six_ops.py bind-obp --asset "$HF"
"$P" -s -B experiments/triad/assets.py fixed-from-h401 \
  --config preparations/operations/configs/obp-u.json --run-dir "$HR" \
  --output "$PWD/reports/obp-H401/compatible-fixed-results.json"
```

绑定后用 `tools/experiment.py prepare configurations/experiments/r15-obp-u-long.json` 验证三种子都能读到同一份正式 10H。OBP EoH 使用独立的 `configurations/experiments/r15-obp-eoh-long.json`。

## 部署和回退

传输新版 ZIP 与 `.zip.sha256` 后，在集群的 `$HOME` 执行。该操作只写新目录。六组长实验包随附核验过的 D06 参照，也包含 `r15p5-site-no-api.json` 三种子现场配置。

```bash
cd "$HOME"
NAME=triad-candidate-runtime-20261121-r15-six-long
R="$HOME/hdl-deploy/$NAME"
P="$HOME/hdl-envs/portable-v2/bin/python"
sha256sum -c "$NAME.zip.sha256" &&
  { test -d "$R" || { mkdir -p "$R" && unzip -q "$HOME/$NAME.zip" -d "$R"; }; } &&
  "$P" -s -B - "$HOME/$NAME.zip" "$R" <<'PY'
import hashlib, json, sys, zipfile
from pathlib import Path

archive, root = map(Path, sys.argv[1:])
with zipfile.ZipFile(archive) as bundle:
    manifest = bundle.read("release.json")
if (root / "release.json").read_bytes() != manifest:
    raise SystemExit("部署版本与发布包不一致")
files = json.loads(manifest)["files"]
for name, digest in files.items():
    if hashlib.sha256((root / name).read_bytes()).hexdigest() != digest:
        raise SystemExit(f"部署文件校验失败：{name}")
print(f"部署文件校验通过，共 {len(files)} 项")
PY
```

printf '%s  %s\n' '694fb50220664430d8a018640a411782bdb8d5b96cb70424e17209b41d2b360a' "$REF" | sha256sum -c - &&
  mkdir -p "$R/preparations/operations" && cp -n "$REF" "$R/preparations/operations/tsp-reference-r15.json" && cd "$R"
