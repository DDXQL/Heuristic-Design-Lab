# 实验结束后如何整理、画图和保存

本文说明r4新增的离线收尾入口及其保存边界。正式求解、测试集评价和GitHub推送分别执行；整理已有记录本身不请求模型、不求解。

## 1. 先确认这次运行确实结束

核对运行终态、写入进程、锁、在途请求和预算账本。区分完整完成、安全暂停、失败停止和未知请求；暂停不能登记为完成。Slurm运行还需确认作业终态，并取回结果、核对文件哈希。

每次运行使用唯一实验编号，记录问题、实验组、搜索种子、求解种子、代码提交、实际配置及哈希。分支名用于辨认开发工作；准确复现依靠运行时的代码提交、配置、数据和依赖身份。代码存在未提交修改时保留实际源码差异或快照，不能只写当时HEAD。

## 2. 保存两份用途不同的材料

| 材料 | 应保存的内容 | 用途 |
| --- | --- | --- |
| 完整证据包 | 实际配置、协议、H及顺序、数据及合法可保存的依赖、参照值、版本、真实Prompt和响应、候选程序、父代、评价结果、逐实例成本、事件、失败、预算、检查点、日志、环境说明 | 核对与复现，保留原始记录 |
| 精简成果包 | 中文报告、冠军程序、逐实例CSV、逐次生成CSV、逐代CSV、成本摘要、演示图、图的数据及作图脚本、完整包位置和SHA-256 | 阅读、汇报及GitHub展示 |

完整包不含密钥、凭据、虚拟环境或无关缓存。打包时检查源文件、Prompt、响应和日志是否夹带秘密；需要脱敏时生成单独副本并记录处理范围，不覆盖原始证据。外部数据受许可限制时保存取得方法、版本和哈希，不擅自公开。

## 3. 固定输出这些图

| 图 | 说明什么 | 数据要求与边界 |
| --- | --- | --- |
| 最好训练J随演化尝试变化 | 什么时候取得进步、什么时候长期停滞 | 横轴明确为演化尝试；初始化单独标出，失败和重复占预算，不能从横轴删除 |
| 候选成绩与每代种群变化 | 新生成的程序如何变化、哪些进入种群 | 区分交叉和变异、父代和子代；内部负J转回J后标注，不能混用历史负Fitness |
| 生成结果分类 | 有效、重复、解析失败、评价失败、传输失败等发生多少 | 分类依据账本，标明互斥关系或重叠关系，未知保留未知 |
| 冠军变化及局部父子关系 | 冠军在哪次被替换、由哪些父代产生 | 保存完整关系CSV，图只展示冠军相关路径，避免1000个节点挤在一张图上 |
| 冠军在各实例的结果 | 哪些题较好、哪些题较差 | 区分训练、验证、测试；基线只有条件匹配时才叠加 |
| 双层方法的H选择图 | U在不同实例、不同求解阶段选哪些H | 优先复用已存member_sequence；h_calls可能是评分调用次数，不能直接当H选择次数 |

所有展示图保存PNG，另存SVG或PDF供放大；图题写明问题、实验组、种子、数据用途和评分版本，并附来源CSV及生成方法。缺少已有记录时明确缺失，不能为补图自动重跑。生成记录只能说明搜索过程，不能据此证明模型内部推理正确或某项状态有因果作用。

多种子完成后，再增加逐种子曲线、均值与标准差、每个种子的冠军表及同条件比较图。失败、未启动和中止的种子另列；均值旁说明实际纳入数。单个种子不画重复实验的波动带。测试成绩仅来自按冻结协议实际执行的测试，不为收尾提前访问测试集。

## 4. 报告应让人看懂

报告交代实验比较什么、实际采用的配置、完成情况、冠军身份和选择规则、逐实例成绩、成本、主要变化、局限和下一步。

分别列出H构建、初始化和演化尝试；实际请求、有效不同候选、失败、重复、评价次数、token、已核实费用、运行与暂停时间不能混为一项。不明费用写未知。两次共享的批次耗时不能简单相加冒充墙钟时间。

目前Mac单种子运行fjsp-u1000-20261112-mac-seed-501已有完整搜索结果：初始化8次、演化1000次，冠军G076-001-CROSS，训练J为1.028064685792435。已有summary.json、champion.py、candidates.csv、generations.csv、per_instance.csv、api_intervals.csv和两张SVG曲线。r4只读这些导出生成展示图与归档，不重跑原实验。以上仍是单种子训练搜索结果。

## 5. GitHub如何区分版本

建议按开发主题维护少量分支，例如codex/triad-experiment-package；每次运行和种子用独立结果目录区分，不为每个种子建立代码分支。

代码版本、实验结果和发布版分开记录：

- 代码分支：继续开发的工作位置。现有工程分支为codex/fjsp-eoh-gap-prep-20261113，不因整理结果就自动改名或切换。
- 代码提交：每次实验实际使用的确切代码身份。后续收尾工具的提交另记，不能替代旧实验运行时的版本。
- 实验目录：按问题、实验组、种子及运行编号区分；同一实验暂停恢复使用原身份。
- Git标签：给审核后的代码或成果版本起固定名字。只标记实际提交的内容；标签本身不包含未入Git的原始实验文件。

GitHub普通提交优先保存代码、配置、说明、作图脚本、精简CSV、冠军和适量图片。完整原始结果使用经过大小、隐私和许可检查的Release附件、Git LFS或独立备份；具体方式在上传前选择，不把整个runs目录直接加入Git。

推送前交付本地可审阅清单：目标仓库、分支、提交、标签、将上传的文件、排除项和大文件。推送只包含本次选定内容，不夹带其他工作树的未完成修改，不强推。README提供“版本—实验编号—结果—完整包位置及哈希”的对应表。记录本地提交和远端推送两种状态，不能混称已上传。

## 6. 完整备份与清理

完整证据用Windows可解压ZIP保存到/Users/DDXQL/Developer/transfer-outbox，附文件清单、SHA-256和核验说明。用户通过UU传至Windows后核验哈希及解压内容。依次记录已打包、已传输、已核验；未完成异机核验不能写成已有备份。

仍被后续比较、恢复、导出引用的本地文件继续保留。只有用户确认异机核验成功并确认依赖已处理后，才讨论清理。本机压缩包或GitHub代码推送不能自动替代完整证据备份。

## 7. 收尾入口的交付标准

复用现有export与summary，补足检查、画图、成果清单、完整包和GitHub待推送清单。命令先支持check-only；只读取指定运行，派生文件放新目录，重复执行不覆盖原始记录，不重新求解，不请求模型，不自动推送。

先用已完成的Mac FJSP 501作为实际离线样例，再复用到六组、多种子及集群取回结果。旧r3部署ZIP保持不变；新增功能形成新提交和r4包。六组执行准备证据继续复用r3，本轮只补离线收尾检查，不追加请求或求解。

## 8. 现在怎样操作

在Mac终端使用已有带Matplotlib的分析Python；当前可用的是`/opt/homebrew/opt/python@3.13/bin/python3.13`。原portable-v2执行环境未安装Matplotlib，保持原样；check-only仍可执行并报告图形依赖是否存在。不默认安装或改变运行环境。新主机的可选依赖单列在requirements-closeout.txt。

以下检查只读，不写原运行或派生目录：

```bash
cd /Users/DDXQL/Developer/Heuristic-Design-Lab-fjsp-eoh-gap-20261113
/opt/homebrew/opt/python@3.13/bin/python3.13 -B experiments/triad/closeout.py check-only --run-dir /Users/DDXQL/Developer/Heuristic-Design-Lab-fjsp-mac-20261112/runs/fjsp-u1000-20261112-mac-seed-501
```

样例成果版本v1及其完整ZIP由本轮实际生成。需要再次整理时指定全新目录与文件名，例如下面的v2；这是纯离线处理，可能花几分钟压缩及逐成员核验约1.15GB原始证据，不是重新实验。重复执行相同目标会拒绝覆盖。

```bash
/opt/homebrew/opt/python@3.13/bin/python3.13 -B experiments/triad/closeout.py build \
  --run-dir /Users/DDXQL/Developer/Heuristic-Design-Lab-fjsp-mac-20261112/runs/fjsp-u1000-20261112-mac-seed-501 \
  --output results/fjsp-u501-closeout-20261114-v2 \
  --archive /Users/DDXQL/Developer/transfer-outbox/fjsp-u501-closeout-20261114-v2-full.zip
```

省略archive只生成精简成果，不冒充完整备份。build默认只接受已完成且无锁、无未知任务的运行；安全暂停可显式带allow-incomplete，报告仍标为暂停。缺少导出时须用该运行原冻结版本的export在允许的位置导出，不用新代码改写旧原件。此入口不运行export去修改原目录。发现疑似密钥会停止并只报告文件位置，不打印秘密、不替换原件；脱敏副本须另行审阅。

多种子已有batch.py的Summary.json后，用同一工具只读整理；下例路径须替换为实际完成批次的汇总路径，不存在时不能当已生成文件。

```text
closeout.py check-only --summary 实际Summary.json
closeout.py batch-report --summary 实际Summary.json --output 新派生目录
```

批次报告复用已有均值／样本标准差，保留全部失败、暂停和未启动项；逐种子曲线只读已有candidates.csv。波动带只在已有数据且有效数不少于2时绘制，不补中止区间。各运行完整原始ZIP仍分别保存，批次摘要不代替原始备份。

GitHub清单只列待审阅内容，不执行add／push。原运行不进Git；精简成果可在审阅后单独选入本地提交。推送前还须核对整个分支相对远端的待推送提交，不能以一份文件清单保证整个分支只包含这些文件。Git标签建议审核后创建，当前不自动创建。原始备份通过UU传到Windows并核验前，不删除Mac原件。
