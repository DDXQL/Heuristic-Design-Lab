## 验证记录

42 项测试通过：原有26项加新增16项，覆盖调度、候选约束、超时、失败处理、互补选择、
提示信息边界、预算及恢复。数值执行还拒绝隐式 None 分支和 round 的超大 ndigits，同时保留省略 ndigits 时返回 int 的 Python 语义。使用现有项目的 `PYTHONPATH=code` 约定，不修改旧测试。
首次漏设路径造成导入失败，修正测试命令后通过，不将失败隐去。

训练全链路使用现有 manifest 的21个 train，每个有效候选均评价完整批次。
四组各2代、每代10次模拟请求；共享初始化5次；H适配初始化2次、演化20次，合计107次。
所有这些都是 mock 请求槽位，真实 LLM 调用为0；不记录虚构 token 或费用。
各轮完整运行及完成后恢复时间见证据 JSON；完成后恢复无新增候选请求/评价。
这反映开发运行开销，不用于 B0/B1/B2/P 的科研性能或成本结论。

微型回放来自手写 state_u 与 EFT/SPT 演示 H：共3步，合法动作数4/4/2，
makespan=4、V5 LB=4、score=-1。七状态输入、动作评分和甘特图与执行记录一致。
HTML约5KB，所有阶段事件约36KB，完整运行记录约1MB。展示页面本身没有模型调用。

开始时115个已跟踪文件的 SHA-256 最终全部一致，包括冻结规则和 v1/v2。
相邻 EoH-S 工作区也未修改；只登记来源 commit/文件哈希和已存在的 dirty 状态。
第五个算子 M3 的简化含义依据 [EoH原文第3.4节](https://arxiv.org/html/2401.02051v3)，
I1 仅初始化。新提示是向七状态 U 接口的明确迁移，不声称逐字重现原任务提示。

完整原始记录在本地忽略目录 `runs/research_v1_train_verified_20261005`；
可提交的精简证据在 `tier2_research_offline_v1_evidence.json`。

## 下一阶段的具体前置

1. 确定 provider、接口地址、模型标识、可用 usage 字段和本机认证方式；密钥不进 Git。
2. 接入有明确网络 deadline、单次请求、无隐藏重试、可采集实际请求/token 的真实 transport，并先用本地模拟服务验证。
3. 分别确定 H、共享初始化、试跑及正式重复的请求/token/费用预算；明确 K、R 和执行资源。
4. 真实生成 H 后验证每个成员并审查代码支持的行为说明；固定代码/编号/哈希。当前 mock 说明未审查，不能替代正式 H。
5. 小预算试跑通过后，锁定协议再做正式训练搜索及验证集选择；最后冻结 U* 后才独立 test。
