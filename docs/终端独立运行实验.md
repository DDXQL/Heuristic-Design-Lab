## 先区分运行种类

| 运行 | api_mode | evaluation_mode | 输入与含义 |
| --- | --- | --- | --- |
| Mock演化 | mock | mock | 人工响应与人工分数，检验任务/谱系/恢复；不证明优化效果 |
| Mock生成、真实求解 | mock | solve | 真实问题构造及复检，候选由Mock产生，不能称LLM搜索成果 |
| 固定候选真实求解 | fixed | solve | G=0、import P0；合成实例用于工程验证 |
| 正式训练数据评价 | fixed | solve | 显式train清单与冻结H/P0，只评价，不生成候选 |
| 真实LLM搜索 | real | solve | 模型API生成＋真实训练求解；配置、凭据、预算和CLI开关均须满足 |

本轮演示不调用真实API。示例H为3个手写规则，编号按文件顺序，无训练排名先验。
真实模式已有传输路径，但尚未做线上端到端验收，也没有确定正式模型、10H来源、数据划分和预算。
`*.real.template.json`是待填写模板：endpoint和model为占位值，训练清单路径尚待用户指定，授权默认false。
不要把模板准备就绪或替身测试通过写成真实搜索完成。

## 复制这些命令完成一次Mock流程

在VS Code用“打开文件夹”打开项目，然后打开终端：

```sh
cd /Users/DDXQL/Developer/Heuristic-Design-Lab
.venv/bin/python -B experiments/common/manage.py --problem fjsp doctor
.venv/bin/python -B experiments/common/manage.py --problem fjsp preview --config experiments/common/configs/terminal-demo.mock.json
.venv/bin/python -B experiments/common/manage.py --problem fjsp prepare --config experiments/common/configs/terminal-demo.mock.json --run-dir runs/my-terminal-demo
.venv/bin/python -B experiments/common/manage.py --problem fjsp run --run-dir runs/my-terminal-demo
```

prepare要求全新目录；不要重复使用已有目录。preview不发送请求、不求解；doctor可加`--config`检查输入、H和凭据是否存在，只输出存在性，不输出密钥。
启动后终端逐批打印JSON：阶段、已完成代数、目标代数、完成候选数、已评价最优Fitness、初始化/演化预算和在途任务。
Mock分数有`score_is_mock=true`标签；“generation”是已完成代数，当前代在途信息见tasks和plans。

运行只需几秒；要完整观察，可立即在另一个VS Code终端执行：

```sh
cd /Users/DDXQL/Developer/Heuristic-Design-Lab
.venv/bin/python -B experiments/common/manage.py --problem fjsp status --run-dir runs/my-terminal-demo
.venv/bin/python -B experiments/common/manage.py --problem fjsp pause --run-dir runs/my-terminal-demo --wait
.venv/bin/python -B experiments/common/manage.py --problem fjsp status --run-dir runs/my-terminal-demo
.venv/bin/python -B experiments/common/manage.py --problem fjsp resume --run-dir runs/my-terminal-demo
.venv/bin/python -B experiments/common/manage.py --problem fjsp export --run-dir runs/my-terminal-demo
```

status只读，可在运行中使用；在途预留是正常状态，不代表可以另起一个run。
pause提出请求，`--wait`等待当前有界批次排空及协调者释放锁；默认等300秒，可用`--wait-seconds`调整等待时间。
超时只说明尚未收尾，应继续status核查，不杀进程/删锁/重复发送。
resume只接受安全paused，继承原协议、预算、种群、抽样计划和随机数状态；不能用改配置的方式续跑。
export不重新生成或求解，只读取已存在证据，默认写入该run的exports。

也可用候选边界暂停，适合单终端练习：

```sh
.venv/bin/python -B experiments/common/manage.py --problem fjsp run --run-dir runs/another-new-demo --max-tasks 6
```

此目录须先prepare。批次会安全排空，所以实际完成数可能略大于6。已经completed的运行不应resume；要重做就prepare新目录。

## 配置及正式输入格式

路径相对配置文件目录解析，再由prepare冻结为输入内容及来源哈希。配置文件后续修改不会改变已创建run。

| 配置字段 | 作用 |
| --- | --- |
| problem、state_schema | fjsp/tsp及`constructive-common-v1-fjsp/tsp`；schema省略时由problem确定 |
| data_manifest、h_file、p0_file | 数据清单、冻结H、可选导入P0；Mock不填时使用工程fixture |
| initialization | llm通过请求收集N个有效唯一U，或import恰好N条并重评 |
| population_size、generations | N与G；fixed须G=0；演化N至少2 |
| search_seed、solve_seed | 抽样种子与合成数据生成身份分开；现有构造器确定性，不引入额外求解随机性 |
| api_concurrency、evaluation_concurrency | 请求/候选CPU并发独立配置；实例内串行 |
| initialization_candidate_cap、initialization_request_cap | 初始化独立上限；不足N则初始化未完成，不借基线 |
| generation_request_cap、api_attempt_cap | 演化上限至少2NG；真实总尝试上限覆盖初始化＋演化；每逻辑请求一次尝试，不自动重试 |
| instance_timeout_seconds | 当前固定T30完整首解/复检行接收，另2秒退出宽限，非单次T15 |
| window、enabled_groups | 历史窗口与特征组 |
| provider、real_requests_authorized | 模型协议/端点/超时/输出限额及配置授权；密钥仅指定环境变量名 |

数据清单JSON：

```json
{"problem":"fjsp","split":"train","instances":[{"path":"train/Behnke1.fjsp","sha256":"填写文件SHA256","file":"Behnke1.fjsp"}]}
```

实例路径相对清单目录。每文件必须声明正确SHA256；可用`shasum -a 256 路径`取得。
FJSP支持已有`.fjsp`文本或JSON `{ "machines": 机器数, "jobs": [ [ [[机器编号,加工时间]], ... ] ] }`；JSON机器编号从0开始，加工时间为正整数。
TSP支持JSON `{ "coordinates": [[x,y], ...] }`，沿用现有至少3城市、单位正方形欧氏距离接口，**不是任意TSPLIB距离矩阵适配器**。
仅接受train或synthetic-development；不得把确认集重标train。程序检查声明和哈希，不代替研究者审查划分来源。

H文件为按冻结编号排列的候选列表，或`{"members":[...]}`。每项为`description,code,key,kind="h"`；也接受每项candidate包装。使用现有问题H签名和校验器验证，顺序不按新成绩重排。
P0列表每项为`{"source":"可核验来源", "candidate":{"description":"...","code":"...","key":"...","abi":"pure-routing-state-v1"}}`。
可参考`experiments/common/fixtures/`内已认证工程格式；替换H数量后必须重新生成/校验U的key。

## 真实搜索的接入与默认拦截

复制`fjsp-real.template.json`或`tsp-real.template.json`为自己的配置，填写真实端点/模型、train清单和H来源。
本轮不设置真实凭据，不运行下方真实启动步骤；它们是正式预算获准后的操作说明。
先doctor/preview，再prepare。模板默认授权false，`run`即使带`--allow-api`也会在请求前拒绝。
正式启动须**prepare前**将自有配置授权改为true，并固定请求预算；prepare之后不可修改已冻结协议。
凭据从配置中`provider.api_key_env`指定的环境变量读取，可在终端隐藏输入，勿把值写到命令历史或Git：

```sh
read -s 'HEURISTIC_API_KEY?API key: '
export HEURISTIC_API_KEY
```

以上为Mac默认zsh用法。配置内只保存变量名，doctor只报告是否存在。
正式run和每次resume还须显式附`--allow-api`；缺配置授权、缺启动开关或缺环境凭据均先拒绝，无请求。
完成输入、模型、预算与授权配置后，真实模式仍复用同一组命令（本轮未执行）：

```sh
.venv/bin/python -B experiments/common/manage.py --problem fjsp doctor --config experiments/common/configs/my-real.json
.venv/bin/python -B experiments/common/manage.py --problem fjsp preview --config experiments/common/configs/my-real.json
.venv/bin/python -B experiments/common/manage.py --problem fjsp prepare --config experiments/common/configs/my-real.json --run-dir runs/my-real
.venv/bin/python -B experiments/common/manage.py --problem fjsp run --run-dir runs/my-real --allow-api
# 另一个终端：
.venv/bin/python -B experiments/common/manage.py --problem fjsp status --run-dir runs/my-real
.venv/bin/python -B experiments/common/manage.py --problem fjsp pause --run-dir runs/my-real --wait
.venv/bin/python -B experiments/common/manage.py --problem fjsp resume --run-dir runs/my-real --allow-api
.venv/bin/python -B experiments/common/manage.py --problem fjsp export --run-dir runs/my-real
```

客户端使用项目现有有界传输，响应、usage及元数据保存在responses；未知usage不虚构费用。
预算按协调者预留尝试计数；sent_confirmed为传输回调确认发送，硬崩溃可能留下未知在途，不把预留数当精确已付费数。
第一次线上验收、提供方实际协议/模型兼容性及正式训练规模稳定性尚未验证；须先小预算验收后再启动较长搜索。

## 终端独立运行与本机持续运行

终端Python不要求Codex持续推理，因此无需让聊天页轮询实验；真实LLM生成仍消耗API费用。
并发通常缩短等待时间，不减少计划候选数、请求总数或必然降低费用。CPU扩容不能替代API服务端限流管理。

前台运行时保持终端打开。较长任务可在本机用nohup和caffeinate（先prepare）：

```sh
mkdir -p logs
nohup /usr/bin/caffeinate -i .venv/bin/python -u -B experiments/common/manage.py --problem fjsp run --run-dir runs/my-terminal-demo > logs/my-terminal-demo.log 2>&1 < /dev/null &
tail -f logs/my-terminal-demo.log
```

这里使用Mock目录；真实命令仅在另行授权后增加`--allow-api`。
nohup可减少关闭终端导致挂断的影响；caffeinate -i阻止空闲休眠，**不能保证合盖、断电、注销或重启后继续运行**。
中断后先status和日志；有残留锁/未知在途时不得删除锁重新run。
源码修改使旧run执行身份失效：可用status查看旧快照；需要原代码版本恢复或新目录重新冻结，不自动升级旧checkpoint。
