版本：v1.0；日期：2026-10-05（Asia/Manila）。

代码依据：研究分支 `codex/tier2-offline-research`，检查快照 `7b342c5`。
方法依据：[框架方案 V5](https://app.notion.com/p/3e904e0510d781eba9b5f8b9114e2e70)、

## 1. 问题与结论

正式 H、LLM 生成 U、正式演化和 validation/test 可以继续开发并执行。
上一轮交付完成的是 P1–P6 的**离线原型与 mock 验收范围**，并未交付完整正式实验系统。
“流程能用模拟响应跑通”不能证明真实模型生成、正式预算控制或独立测试已经完成。

尚未完成有三类原因：

1. **范围与决策尚未落实。** 用户最初要求不调用 LLM，随后授权推进离线计划；
   当前没有明确的真实 provider、模型、生成预算、正式 H 大小 K 和重复数 R。
   写 PRD 也不等于批准付费请求或立即打开研究 test。
2. **我仍需完成真实运行相关代码。** 真实请求适配、正式 H 载入/导出、独立参数配置、
   配对重复驱动、validation 选择、冻结记录、test 与分析入口尚未实现。
   这些不是仅靠填写 API key 就能补齐的工作，其中大部分可先自主离线完成。
3. **研究步骤有先后依赖。** 正式 U 搜索要使用已经生成并冻结的 H；validation 要评价
   正式搜索的最终种群；test 要等 U* 和协议冻结后进行，避免结果反向影响设计。

现有冻结 Tier1 曾有自己的 validation 记录；这不代表新的 Tier2 U 已完成 validation。
不能把 Tier1 历史记录直接作为新实验结果，也不能混用两个版本的归一化分数。

## 2. 产品目标与交付范围

目标：建立一个可复现、可限制成本、可审计的本地研究执行系统，完成
**真实生成并冻结 H → 真实初始化/演化 U → validation 选择 U* → 冻结后独立 test → 报告**。

使用者是本项目研究者。研究者应能查看阶段、成本、失败和结果，而无需逐项手工接管正常运行。
LLM 只在离线生成候选代码时调用；在线排程的每一步调用的是本地 Python U，随后调用本地 h。
排程每一步不发送模型请求。

本期交付：真实 provider 适配与本地服务测试、正式配置/阶段入口、正式 H 资产、
共享初始化、四组配对实验、选择与冻结、独立 test、统计/成本/复现报告。
真实实验数据必须实际运行后才能交付；实现入口本身不算实验完成。

不纳入本期：改变冻结 Tier1、GP/SPSO、额外奖励反馈模块、状态级优势标签、
训练时用 validation/test、云网站、模型驱动的可视化、任意 Python 通用沙箱。
若后续需要放宽候选语言，必须另立实验版本并统一应用于全部实验组。

## 3. 保持不变的实验契约

| 契约 | 要求 |
| --- | --- |
| U 输入 | 六个 float：progress、candidate_pair_ratio、remaining_work_mean/std、machine_ready_mean/std；一个 int：previous_heuristic；定义复用 v2，首步 previous=-1 |
| U 调用 | 每排程步骤仅调用一次；终止状态不调用；返回 `type(id) is int` 且在 `[0,K)`，拒绝 bool、越界、None 和异常 |
| h 输入 | 单个合法工序—机器动作的七项原始量纲特征；不得给 h 混入 U 的状态摘要 |
| 动作选择 | 本步仅用选中的 h 给全部合法动作评分，最高分执行；平分按 job 再 machine 索引；不能把 U 选择塞入逐动作 priority 回调 |
| 评价 | 独立检查完整排程；V5 LB 不对工作量/M取整；score=-makespan/LB；fitness 是完整 split 的逐实例 score 算术平均 |
| 无效候选 | 任一实例报错、超时、不合法或不可行，整体无效、mean 为 null；成功前缀仅作诊断，不对子集求平均、不回退、不补生成 |
| 去重 | 使用规范化 AST 代码键；同分或相同分数向量不等于同一代码；不声称语义等价去重 |
| 候选语言 | 默认沿用已测试的 closed numeric AST-v1 和数值限制，所有组一致；禁止外部访问、随机性和跨次可变状态；每条正常返回路径有返回值 |
| 冻结基线 | 保留 Tier1、v1/v2 和现有规则；在新协议比较冻结规则时，以原 makespan 重算 V5 指标，注明协议区别 |
| 信息边界 | 初始化不给 H 代码/行为；演化按组提供 H；提示不包含父代逐实例分数、错误轨迹、优势标签、历史奖励；fitness 只供外部选择 |

## 5. 功能需求及验收标准

### FR-01：正式配置与执行前检查（P0）

建立新的正式实验版本与入口，保留 `research_v1/run_offline.py` 的 mock 语义。
分别配置 provider、H 生成、共享初始化、U 搜索、选择、test、预算和资源。
`K`、`N`、交叉父代数、变异父代数互相独立；配置不能以“两个 h”推断正式 K。

验收：配置错误在请求前拒绝；N=10时交叉实际选5个不同父代；mock H 不能进入正式搜索；
H、数据、实现、提示、模型、语言限制、资源和预算产生不可混淆的配置哈希。
实现指纹覆盖实际导入的调度/状态/规则/模板依赖，并记录 Python 与依赖版本；
不能只哈希入口文件而遗漏影响执行的模块。真实数据哈希在对应允许阶段核验，
预检可检查 validation/test 的 manifest 元数据，不提前读取其数据内容。
阶段标记由执行结果产生，不能仅把 `llm_called=false` 等常量改成 true。

### FR-02：真实模型 transport 与预算账本（P0）

通过明确的 provider 协议发送一次候选请求，关闭 SDK/HTTP 层隐含重试。
配置连接、读取及总等待上限；记录请求 ID、状态、文本、真实 usage、耗时与错误类型。
记录请求前预算预留、发送状态和响应结算；H/初始化/试跑/正式搜索分账并受总预算约束。

验收：本地模拟服务覆盖成功、鉴权失败、429、5xx、超时、畸形响应、截断输出、缺 usage。
任何失败消耗相应尝试，不修复或自动重新请求同一候选；下一候选仍需预算允许。
完成后恢复复用记录；中断且发送情况不明时，不重新发送、不声称精确知道供应商计费。
硬请求上限严格执行；token/金额使用可靠预留上界和结算，无法保证时明确为估计/未知，
不能宣称有不可验证的费用硬上限。真实 usage 不可用时记 null，不用字符数冒充 token。
认证信息和含密钥错误字段经过日志脱敏；超出上下文长度时停在预检/当前阶段，不能删父代代码或改实验组条件来继续。

### FR-03：真实 H 生成、审查和冻结（P0）

接入已审计的 EoH-S 互补选择/生存机制，以完整 train 的分数向量评价真实生成的 h。
明确本研究适配版本与上游线程实现的差异，不宣称全量原文/上游复现。
生成请求预算与 U 搜索预算分开；不从 validation/test 判断 H 的好坏或补选成员。

验收：生成至少配置要求的 K 个有效、代码不同的成员，再按锁定的互补生存规则确定 K；
不足 K 则明确失败，不缩 K、不塞入手写 EFT/SPT 充数，不重复启动直到碰到满意结果。
记录成员0..K-1、完整代码、源候选 ID、代码哈希、train 分数向量、生成模型/配置/请求出处。
每个行为说明经过代码审查和固定动作样本核对，描述计算行为；不能声称存在未验证的状态级优势。
说明未核对时保持未审查状态，正式冻结门禁拒绝；审查不得暗改生成代码。
代码修改需要新候选身份、重新完整 train 评价与新资产版本。

导出 `H_frozen.json` 及资产哈希，独立 loader 核对 K、编号、代码键、接口、出处和审查状态。
互补收益为0或多个成员分数相同仍如实记录，不以同分去重，不保证动态 U 一定因此获益。
H 的整实例互补性不代表状态级互补性，七状态输入也未必足以识别每步最佳 h；
这些属于后续实验要检验的限制，不能通过虚构标签或额外奖励反馈绕过。

### FR-04：真实共享初始化与 U 候选闭环（P0）

LLM 每次输出一份描述和完整 U；初始化仅给任务、七状态接口、K及合法编号，不给 H 代码/行为或父代。
代码通过现有解析、精确接口、纯数值限制、编号检查、确定性复核及全 train 排程检查。

验收：取得 N 个有效且代码不同的 U，并持久保存共享初始种群资产；最多初始化上限次请求，
不足 N 则报告初始化失败，四组不启动；不偷偷补调用或重新挑种子。
一份共享初始化绑定对应 H/协议，只允许该配对重复的四组复用。
常量 U 合法，不要求切换或覆盖全部成员。任一 train 失败只留诊断，不产生部分 fitness。

### FR-05：四组正式 U 演化与配对重复（P0）

| 组别 | H 信息 | 算子 | 主要比较 |
| --- | --- | --- | --- |
| B0 | 仅 K 与合法编号 | E1/E2/M1/M2/M3 | 基础迁移参照 |
| B1 | 固定 H 的代码及核对过的说明 | 同 B0 | B1-B0：H 信息 |
| B2 | 同 B1 | 通用交叉/变异 | 两算子配置参照 |
| P | 同 B1 | V5 特化交叉/变异 | P-B2：特化提示 |

复用已有代际引擎，增加实际 transport、正式参数和预先固定的 R 次配对运行驱动。
每代父代不变；权重与1/(N+r)成正比，多父代无放回；合并父代与有效子代保留前 N，
train 同分按稳定 ID。每个子代一次请求，只属于一种算子；无效/重复消耗尝试和调用预算。

验收：同一重复的四组 H、共享初始化、模型采样设置、数据顺序、资源与调用上限一致；
算子配额可逐请求核对；最终种群保存完整出处和全 train fitness。
请求数相同不能宣称成本相同，H 信息造成的输入 token 差异单独报告。
保存失败或未完成重复，不追加未登记重复直到得到更好的结果。
P-B0 只能支持整体方法比较，不能单独归因特化提示；也不能直接推断每步 U 优于每实例 U。

### FR-06：validation 选择与最终冻结（P0）

增加分阶段 loader/evaluator：生成/演化阶段仅可加载 train；选择阶段需要已完成的
最终种群及阶段凭证才可读取固定11个 validation；不能在每代反复评价 validation。

验收：每组每重复只对其最终种群做完整 validation，以均分最大选择 U*，平分按预设稳定 ID。
任一实例失败则该候选 validation 无效；若组内均无有效候选，记录选择失败，不再演化或替补。
同一 H 的固定单条 h 参照也在 validation 选择一次并固定，不能到 test 上按实例择优。

冻结记录包括 H、各组各重复 U*、固定 h 参照、数据 split 哈希、实现/状态/LB/评分、
提示、模型设置、资源/语言限制、预算、种子和报告方法。
validation 是模型选择证据，不能作为独立泛化结论，也不反向修改 H 或生成提示。

### FR-07：独立 test 与阶段门禁（P0）

test 入口仅接收通过冻结检查的资产，读取固定28个 test，以相同排程/评分/资源约束评价。
test 的候选执行器不创建模型客户端，不发送生成请求，也不向候选开放文件或网络。

验收：冻结缺失、mock 标记、K/编号/代码哈希不匹配、协议变化均拒绝 test。
输出全部实例的 makespan、LB、score、可行性、时间和失败；任一失败不能用成功子集
伪造完整 test 均分。默认保存整批有效/无效状态，缺失或失败均分为 null。
修复执行器错误需新版本与记录，不能悄悄覆盖旧测试结果；不得利用 test 修改 U/H/提示。

### FR-08：统计、成本与可复现报告（P0）

输出各组逐重复/逐实例结果、均值/波动、配对差值、计划与实际完成的重复数、失败率。
统计方法在首次 test 前登记；有效配对数及排除原因显式列出，不仅报告最佳一次。
小重复数以探索性证据说明其范围，不承诺统计显著或 P 必然获胜。

成本分列 H 生成、共享初始化、各组演化、validation、test、在线排程；保存请求数、
实际/未知 token、耗时、候选有效率、评价数和最终运行资源。费用标明供应商账单或
按已核对价目计算的估计及日期，不能把后者称为实际扣费。
在线测量将确定性复核/开发记录开销与部署式单次排程开销区分，不拿双执行时间冒充单次。

验收：每条汇总可追溯到原始记录；生成机器可读表、Markdown报告及需要时的静态科研图。
保留负结果。可选“所有固定 h 各跑一次后取最小 makespan”只作逐实例参照并计其额外成本，
不能称为动态混用 U 的严格性能上界。
固定 Tier1 canonical 对照若纳入，按新协议计算并标注，与原冻结记录分开保留。

### FR-09：低开销进度与恢复（P1）

延续摘要 JSONL、检查点和只读进度快照。展示当前阶段、组/重复/代、完成实例或候选数、
有效/失败数量、已预留/已发送/待核对请求及预算余额。
默认只记录微型实例完整动作，不扩展为全训练轨迹；网页不触发模型调用。

验收：显示来自实际事件，不造百分比或动画；敏感信息不显示；记录开关不改变 U 次数和排程。
恢复不会重复已完成请求/评价；来源、数据或协议变化拒绝复用旧检查点。
同一运行目录禁止并发写入，前一阶段失败不显示后一阶段已完成。

## 7. 预算草案与停止规则

按四组各1000次演化、每重复共享初始化最多50次：

**U 请求上限 = R × (4 × 1000 + 50) = 4050R。**

| 重复数 | U演化 | 共享初始化上限 | U部分合计上限 |
| --- | ---: | ---: | ---: |
| R=3 | 12000 | 150 | 12150 |
| R=5 | 20000 | 250 | 20250 |

还要单独加 H 生成及试跑请求；validation/test 的本地求解不产生生成请求，但占评价和运行时间。
上述数字是配置估算，不是已授权预算，也不说明金额或任务必然成功。
金额要等模型价格、上下文、输出上限与 usage 规则核对后估计；输入/输出及缓存 token 分开记录。

启动下一请求前检查阶段及总预算；预算不足则停止并保存未完成状态。
429、接口错误、无效代码、重复代码都不能触发候选修复或额外补请求。
不确定的已预留请求保守占用槽位并标记待核对；不能因本地没有响应就断言供应商未计费。
到期或运行资源不可用时保存停止原因；继续运行不得绕过预算或重放未知请求。

## 9. 测试与验收矩阵

| 用例 | 输入/故障 | 必需结果 |
| --- | --- | --- |
| 配置独立 | N=10、K=10、cross=5、mutation=1 | 实际按这些数执行，不继承mock的cross=N/K=2 |
| 请求失败 | 401/429/5xx/超时/畸形响应 | 每候选至多一次发送，计数与限额正确，无隐含重试 |
| 预算不足 | 只剩不足下一请求的预留额度 | 请求前停止；未知计费显式保留 |
| 凭证泄漏 | 模拟密钥出现在错误字段 | 日志/报告脱敏，不把密钥放入提示或Git |
| 正式H门禁 | mock、不足K、编号缺口、代码键错、说明未审查 | 正式搜索拒绝启动 |
| 共享初始化 | 相同重复四组；收集不足N | 一次初始化资产共享；失败时四组不开始、不补请求 |
| 候选失效 | bool/越界/异常/无限循环；后一个实例失败 | 拒绝/实际终止；完整批次mean=null，无成功子集平均 |
| 配对与父代 | 一代中生成更优子代；多个重复 | 子代当代不进入父代；四组同初始资产，重复种子明确 |
| 提示边界 | 父代含内部分数/错误记录；B0/初始化 | 不向提示泄漏；初始化/B0不含不该提供的H代码/行为 |
| 数据边界 | 生成阶段试读validation/test；未冻结时test | 阶段门禁拒绝；离线测试使用合成文件 |
| validation | 一个候选在某实例失败、另一个均分平局 | 失败候选不选；有效者按预登记规则选择 |
| 冻结变化 | 换H、改U/提示/代码/评分/数据后启动test | 旧冻结失效，拒绝混用 |
| 恢复 | 完成/未知请求、完成/未知评价、协议变化 | 完成不重做；未知不重放；协议变化拒绝恢复 |
| 报告 | 某组某重复失败；usage缺失；负结果 | 完成数、有效配对数、缺失和失败披露；不只报最佳或虚构费用 |

42项既有测试作为回归起点；新增测试面向上述实际边界，不为文档改动编写镜像测试。
新增正式入口先以本地模拟HTTP服务与合成split跑通，再进入真实train试跑。
