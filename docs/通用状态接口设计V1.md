# 通用状态接口设计 V1：设计可审阅，旧输入不替换

日期：2026-10-27。本文是本项目设计，不是声称EoH/EoH-S已经提供统一状态。框架已支持问题各自提供状态；这不等于当前两个U接口具有共同语义。

## 1. 当前状态及固定维数在哪里

FJSP旧输入仍是七个标量，metadata命名`fjsp-seven-v1-legacy`；原候选接口版本及函数签名没有更名。`code/fjsp_usage/offline_v2.py::_SchedulingState.features`在每次决策之前计算，`usage_v2/execution.py::construct_usage_schedule`把它们解包给U，终态不调U。

|旧字段|实际含义|
|---|---|
|progress|已提交工序数 / 总工序数Q，不是时间完工比例|
|candidate_pair_ratio|当前合法(job,next-operation,machine)数 / C；C=每个job所有工序最大可选机器数之和|
|remaining_work_mean/std|活跃job的剩余最短加工时间和 / T 的均值/总体标准差；T=所有工序最大可选加工时间之和|
|machine_ready_mean/std|所有机器当前ready时间 / T 的均值/总体标准差|
|previous_heuristic|首次−1；之后上一步最大归一化权重成员ID，同权取小编号，丢失另一成员及权重|

隐含固定维数的关键位置：`research/candidates.py::U_ARGS`与封闭AST/编译、`usage_v2/candidates.py::validate_usage_code`借用旧七参数检查、`offline_v2.py::StateFeatures`、`usage_v2/prompts.py::TASK/prompt_sections`及H01专用模板；trace和旧回归也绑定这些名字。只改字段名或提示词不构成可靠迁移。

TSP的五参数由`problems/tsp/candidates.py::U_ARGS`及`solver.py::construct`规定：progress、current_to_start、mean_distance_current、std_distance_current、previous_heuristic；距离除以sqrt(2)，进度为(visited−1)/(n−1)，闭合回原点是强制边而非一次U选择。metadata命名`tsp-five-v1-legacy`。旧TSP候选语言、几何动作与NN参照保留。

动作级H特征和U状态不是同一输入。FJSP H评分一个工序—机器动作；TSP H评分一个待访问城市。U不能因为换了状态schema就获得完整动作矩阵或调用H。两问题目前不同的Fitness也不会因接口统一而自动可比。

## 2. 三层状态必须分开

1. **解构造状态**：当前已提交的部分解、合法动作、已知实例结构；在线U可使用，不能读取未来选出的排程或确认集成绩。
2. **内层构造轨迹/历史**：前一步输出、使用计数、累计构造成本；若新增存储/输入，需要明确更新时点和初始化。构造解逐步变大，没有单调改进的完整解序列，不能把局部搜索的“改进率”照搬过来。
3. **外层演化状态**：代数、父代Fitness、失败记录、历史经验。可供生成Prompt或种群选择，不属于当前在线U七输入，也不塞进构造状态冒充问题无关信息。

已知实例的加工时间/距离用于计算标准化尺度不属于未来信息；未来候选的完整求解成绩、最终确认集成绩不允许成为在线特征或开发反馈。

## 3. 推荐结构：共同构造量＋显式问题扩展＋可用性

建议下一版使用命名的只读state envelope，分为problem_id、schema_id、phase、common、extensions、availability、history；不把所有问题强行压成同一个固定七维向量。推荐先审阅以下三个共同量，**本轮不计算、不送进U、不替换旧输入**。候选元数据`constructive-common-v0-draft`明确禁用。

以下T为FJSP串行可行成本上界，Dmax为TSP实例最大两点距离，Lpartial为已提交开放路径长度。所有量在选动作前计算，分母只用当前已知实例，均不是最优值/LB。

|拟议共同字段|定义、范围与时点|FJSP计算|TSP计算|增量开销与边界|
|---|---|---|---|---|
|construction_progress|已提交可选决策数/固定总决策数；U调用时[0,1)，提交后更新|len(scheduled)/Q|len(tour)−1 除以n−1；不计强制闭合边|O(1)；要求Q>0、n≥3，终态不调U|
|action_breadth_fraction|当前合法动作数/实例固定合法动作数量上界；(0,1]|legal_pairs/C，C沿用旧定义|unvisited_count/(n−1)|FJSP O(J)，旧features已有计数；TSP O(1)。这衡量相对可行动作容量，不表示同分布难度|
|committed_objective_fraction|当前部分目标负担/已知可行成本上界；[0,1]，只含已提交内容|max(machine_ready)/T|Lpartial/(n×Dmax)|FJSP O(M)或跟踪max后O(1)，TSP累计路径O(1)，Dmax在现有距离矩阵上一次O(n²)。不估计最终质量，不是gap|

FJSP需要预检正加工时间/Q/T/C；零分母不能填0。TSP若Dmax=0（全部重合）则第三字段不可定义，且当前NN参照指标本身也退化：须按预先数据兼容协议拒绝/标不可用，不能按策略成绩筛除。共同字段若选为必需字段则在预检阶段拒绝不兼容实例；若选为可选字段则必须显式missing与availability。不能在运行中静默换尺度。

上述第三字段共同语义只是“已提交负担相对上界”。FJSP makespan与TSP可加路径成本的增长性质不同，同值不意味着相同后续质量；可用于跨问题同名输入的设计，但不预设可迁移收益。

### 可选历史与问题扩展（尚未确定入选）

|拟议字段|定义/归一化及两问题计算|开销、边界与是否共同|
|---|---|---|
|previous_mix_balance|上一步两正权重时2×min(w)，单成员/SELECT为0；两问题都从host实际decode结果取得|O(1)，首次无历史必须missing+available=false；不能用0冒充首次。需新增host历史存储，未启用|
|previous_support/member tokens|上一步实际成员集合/权重，按本问题冻结H命名空间编码|最多2条O(1)；首次missing。成员编号跨问题没有共同含义，不当有序实数；H训练排名编号也不是客观语义|
|FJSP扩展remaining_work_mean/std|沿用活跃job最短剩余工作/T；提交前计算|O(J)，无TSP同义量，放FJSP extension，不给TSP填0|
|FJSP扩展machine_ready_mean/std|沿用机器ready/T；提交前计算|O(M)，TSP没有机器ready，字段在TSP absent|
|TSP扩展current_to_start|当前节点距起点/sqrt(2)，提交前|O(1)，FJSP无同义量，字段absent|
|TSP扩展mean/std_distance_current|当前节点至未访问节点距离/sqrt(2)的均值/总体标准差|O(n)，沿用TSP动作前统计；不与FJSP剩余工作离散程度冒充同义量|

本轮没有选择最终扩展字段集合或历史字段。首次历史未定义、某问题不适用、数据不合法是不同原因，availability应带原因，不能统一填0。概念envelope可以表示null+mask，但**当前在线U语言仍禁容器读取/属性**；它不能直接接收这个对象。

将来若采用`use_heuristics(state)`，必须独立版本化只读命名字段访问、缺失访问规则、封闭AST准入、示例/Prompt和编译，不让任意Python属性/索引突破保护。本轮实现的packet仅用于元数据验证，不是新候选ABI已经可运行。另一可选方案是纯共同三标量签名，成本低但损失问题信息；应由后续对照决定，不在本轮静默选定。

H评分分歧/同状态首选动作分歧不是免费状态：当前U先输出成员，再只调用这些H。若要把所有H评分分歧传给U，会改变执行顺序与成本，必须另立协议，不能借状态设计暗中增加观测。

## 4. 本轮已落实的工程边界

文件：`code/heuristic_design/core/state_contracts.py`。

- 注册FJSP七输入、TSP五输入的legacy metadata schema；纯验证packet的字段顺序、维数、有限值、进度、前一步成员范围。没有接入旧在线求解器，不额外改变其接受语义。
- `require_executable_schema`拒绝跨问题、未知、空或未启用schema；不回落legacy。统一problem路由在进入问题CLI之前做此检查。
- common-v0-draft不可执行。没有新特征计算器、新Prompt、新生成或新缓存。
- 提供**供未来新协议显式采用**的make_binding/assert_same_binding：问题、状态定义、U代码/接口、H有序身份、数据有序身份、LB/NN参照、评价器、归一化、同分、seed都进入身份；缺失/篡改/旧格式拒绝，不自动升级旧缓存或检查点。
- 这个新缓存工具尚未替换当前campaign的身份系统；当前FJSP/TSP继续原有科学/源码绑定。草案不可执行，因此本轮不存在草案策略冒用legacy缓存的入口。未来开启新版状态必须先接入新protocol/cache/checkpoint版本，不能只把executable改true。

可检查而不启动实验：

```sh
.venv/bin/python -B experiments/manage.py --problem fjsp --state-schema fjsp-seven-v1-legacy doctor
.venv/bin/python -B experiments/manage.py --problem tsp --state-schema tsp-five-v1-legacy doctor
# 下条按预期拒绝，退出2，在进入问题/API/求解之前停止：
.venv/bin/python -B experiments/manage.py --problem fjsp --state-schema constructive-common-v0-draft doctor
```

旧直接CLI不接受新版schema参数，其默认语义不变。新旧状态不共享新缓存；不能从旧checkpoint切换schema，也不能因相同维数假定语义相同。

## 5. 信息损失与后续研究选择

共同三量会丢失FJSP剩余工作、机器负载结构，也丢失TSP相对距离结构；common+extension保留信息但削弱“同一跨问题策略无需适配”的主张。归一化到[0,1]只统一范围，不能保证分布、目标贡献或决策含义等价。成员ID即使同号也不是跨问题相同H。

建议优先验证框架各问题独立状态可靠运行，再将“同一共同语义U是否可迁移”作为另一研究问题。下一版尚需确定的科学选择只有：共同三量是否足够；是否加上问题扩展；是否需要历史权重；新候选ABI与缺失访问规则。它们不阻塞本轮目录与legacy兼容交付，但阻塞新版状态的正式质量实验。

## 6. 分阶段验证方案（本轮不执行新科研实验）

1. **目录因素**：固定旧H/U/数据/种子，逐状态、所有合法动作/打分、选中动作、完整解、Fitness及首解/复检比较。已做toy+已认证Behnke1以及TSP小几何例，不把Mock当质量证据。
2. **新接口正确性**：合成边界状态检查进度单调、同状态确定性、不可用字段、终态无U、实例规模变化；分别核对FJSP动作合法和TSP闭合游程。检查schema变化令新cache/checkpoint拒绝，Prompt/AST/host一致。不能只验证能import。
3. **表示改变的质量**：另冻结新版协议，保留同H有序身份、共同P0、候选数/API尝试数、LLM模型/操作、求解seed、数据/LB/指标、归一化/同分/T30/复检；只改变状态表示所必需的签名与说明。先FJSP旧7 vs common，再看common+extension，避免同时改变搜索算法与状态。
4. **跨问题因素**：TSP自身legacy vs共同状态先做等条件对照，再讨论是否能移植同一U；不把分别演化出两份U称零样本迁移。FJSP的−Cmax/LB与TSP的−length/NN不能直接比较数值优劣。
5. **泛化与停止**：独立冻结开发/确认数据；已暴露数据不改名。最终确认不回流调参。不在本轮授权中安排新付费生成或正式质量搜索。

本轮验收见[纯接口测试与范围](../reports/通用状态接口设计-20261027-v1/REPORT_ZH.md)。目录回归与状态设计分别提交，避免将目录变化造成的工程问题误归因于新状态。
