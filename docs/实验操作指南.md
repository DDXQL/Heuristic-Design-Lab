# 实验操作指南

本指南面向自己修改配置、输入终端命令和查看结果的使用者。项目概况和首次本地示例见[项目使用说明](../项目使用说明.md)；想修改算法或提示词时看[实验代码地图](实验代码地图.md)。

说明文字统一使用中文；命令、文件路径、JSON字段和Python函数名保留原名，便于直接复制和对应代码。本文的命令由你自行执行；阅读文档不会启动实验。

## 一、先分清配置、命令和实验目录

|对象|负责什么|你通常怎样修改|
|---|---|---|
|JSON配置文件|使用哪些数据、哪种U空间、多少候选、模型参数和运行窗口|复制示例后，在编辑器里修改副本。|
|终端命令|检查、预览、冻结、启动、查看、暂停、恢复和汇总|按下文顺序执行，配置路径与实验目录保持对应。|
|实验目录（命令中的`--run-dir`）|保存一次实验的配置快照、代码身份、原始响应、进度和结果|新实验使用新目录；恢复使用原目录，不手工编辑账本。|

在VS Code中打开本工作区，通过“终端 → 新建终端”输入命令。以下命令都从仓库根目录执行：

```sh
cd '/Users/DDXQL/Developer/FJSP-Heuristic-Research-h-usage-space'
.venv/bin/python -B experiments/tier2/manage.py doctor
.venv/bin/python -B experiments/tier2/manage.py types
```

这里直接使用项目虚拟环境的Python，不必先激活；`-B`只是避免写入Python字节码缓存。doctor只检查本地环境，不打印密钥、不联网、不求解。

|命令|中文含义|是否启动生成或求解|
|---|---|---|
|`check`|检查配置和来源是否合法|否。|
|`plan`|预览任务列表与预算|否。|
|`prepare`|创建新目录，冻结输入、配置、模板和源码身份|否；会写入本地文件。|
|`run`|首次启动已经准备好的实验|是；是否调用API由配置决定。|
|`status`|只读查看进度和保护状态|否。|
|`stop`|请求在当前候选完成并认证后暂停|不启动新任务，不强杀当前求解。|
|`resume`|从安全暂停的原进度恢复|是；原预算和截止不重置。|
|`summary --write`|根据已有结果保存摘要和CSV|否，不调用模型生成分析。|

## 三、自己配置独立生成U

### 复制示例，而不是改历史配置

```sh
cp -n experiments/tier2/ops/configs/ind-api.json experiments/tier2/ops/learn-ind-01.json
```

`-n`表示目标存在时不覆盖。如果你已经创建过`learn-ind-01.json`，继续查看自己的文件，不重新复制。之后在编辑器打开这个副本。JSON不能写注释，最后一个字段后也不能多留逗号。

|先看这些字段|含义|首次操作建议|
|---|---|---|
|`question`|实验文字备注；不替代实际提示词|写成自己能辨认的说明。|
|`type`|执行流程|`ind`表示每次独立生成U。|
|`space`|U可用的策略空间|`h01`只使用H0/H1互补权重；`ten_h`允许10H的SELECT/MIX。|
|`dataset`|评价数据及用途|第一次保留工程toy；换训练集见第五节。|
|`candidates`|IND新增逻辑候选数|先保留2。|
|`api_attempt_cap`|全实验API尝试上限，含重试|先保留3。|
|`per_candidate_attempt_cap`|每候选最多尝试次数|先保留2。|
|`search_seed`|搜索随机种子|自行指定并记录；IND不把它传成模型seed。|
|`window_seconds`|原执行窗口，单位秒|3600为1小时；最大43200秒。|
|`provider`|模型、接口、生成参数和密钥环境变量名|第一次保留当前示例；不要把密钥写入其中。|
|`real_requests_authorized`|是否允许真实请求|准备真实调用时自行改为`true`。|

例如，第一次只需在副本中核对以下已有字段；这是字段片段，不是完整配置文件：

```json
{
  "candidates": 2,
  "api_attempt_cap": 3,
  "per_candidate_attempt_cap": 2,
  "real_requests_authorized": true
}
```

这代表最多2个逻辑候选、合计最多3次API尝试，不保证得到2个有效程序。完整响应返回后，代码无效或成绩差都不会免费重新生成。调整数量时须满足：新增逻辑候选数 ≤ API尝试上限 ≤ 候选数×每候选尝试上限；每候选最多2次。

### 设置凭据、检查计划、明确启动

在当前终端静默输入密钥：

```sh
read -s LEAFAPI_API_KEY
export LEAFAPI_API_KEY
```

不要把密钥写进JSON、命令字面值或聊天。新终端需要重新设置；后台进程继承启动时的环境。修改模型时同时核对`model`与`expected_response_model`，并确认接口协议及参数支持情况，不只替换模型名称。

下面两条只检查和预览，不调用API：

```sh
.venv/bin/python -B experiments/tier2/manage.py check --config experiments/tier2/ops/learn-ind-01.json
.venv/bin/python -B experiments/tier2/manage.py plan --config experiments/tier2/ops/learn-ind-01.json
```

检查计划输出的`logical_generation`（逻辑候选数）、`API_attempts`（尝试上限）、`max_program_instances`（最多程序—实例评价数）与`max_solve_passes`（最多首解/复检遍数）。确认后：

```sh
.venv/bin/python -B experiments/tier2/manage.py prepare --config experiments/tier2/ops/learn-ind-01.json --run-dir runs/learn-ind-01
.venv/bin/python -B experiments/tier2/manage.py run --run-dir runs/learn-ind-01 --allow-api --background
```

**最后一条会产生真实API调用和费用。**配置中的true与命令的`--allow-api`缺一不可；无人民币硬上限或费用认证前置条件。脚本负责生成、准入、评价、记账和保存结果，不另调模型写总结。去掉`--background`即为前台运行。

如只想练习生成流程，可改用现成`ind-mock.json`，为它单独prepare新目录。模拟响应（Mock）不是模型生成；配置中即使列有provider，也不会因此调用真实API。

## 四、自己配置演化U

```sh
cp -n experiments/tier2/ops/configs/evo-api.json experiments/tier2/ops/learn-evo-01.json
```

编辑副本，将真实请求授权改为true，核对数据与模型。演化与独立生成的区别在这些字段：

|字段|含义|当前H0/H1示例|
|---|---|---|
|`p0`|显式给定的初始群体|5个静态权重程序；先在当前数据上评价。|
|`population_size`|种群规模|5；H0/H1原交叉模板要求保持5。|
|`generations`|演化代数|1。|
|`cross_per_generation`|每代交叉（CROSS）候选数|1。|
|`mutate_per_generation`|每代变异（MUTATE）候选数|1。|
|`cross_parents`|一次交叉的父代数量|5；H0/H1流程不能仅改配置为2。|

新增候选数＝`generations × (cross_per_generation + mutate_per_generation)`。当前示例新增2个候选，另有5份P0评价；EVO的数量不由`candidates`字段控制。当前入口要求交叉、变异每代数量都至少为1。改变代数或每代数量后，也要同步调整API尝试上限。

```sh
.venv/bin/python -B experiments/tier2/manage.py check --config experiments/tier2/ops/learn-evo-01.json
.venv/bin/python -B experiments/tier2/manage.py plan --config experiments/tier2/ops/learn-evo-01.json
.venv/bin/python -B experiments/tier2/manage.py prepare --config experiments/tier2/ops/learn-evo-01.json --run-dir runs/learn-evo-01
.venv/bin/python -B experiments/tier2/manage.py run --run-dir runs/learn-evo-01 --allow-api --background
```

代内父代群体固定，代末才保留下一代。IND的后续提示不接收P0、历史输出或成绩；EVO经父代机制使用群体。新入口不会自动调用LLM补满P0。

## 五、换成train21或自己的实例

本机已有的train21数据清单可以用于新实验。将自己配置中的整个`dataset`对象替换为：

```json
{
  "role": "train",
  "protocol": "runs/baseline-a-supplemental-T30-seed501-20261024-v1/Protocol.json"
}
```

这是`dataset`的值，不是整个实验配置。不要同时保留旧`files`字段。这里仅读取原协议的数据清单并校验文件身份/LB，不恢复或改写旧实验，也不自动复用旧策略成绩。该源目录在本机存在，但不保证新Git检出带有这些忽略的数据资产。

也可用`dataset.files`显式列出工作区内兼容格式的实例路径，入口按既有V5口径计算LB，不自行填写Cmax或Fitness。`role`的工程/训练/确认用途标签分别是`engineering`、`train`、`confirmation`；标签不会把已见数据变成未见数据，确认数据不可进入生成/演化。

换成21实例后，一个策略最多42遍首解/复检；上面的IND最多84遍，EVO含5个P0最多294遍。它们是最坏上限，缓存、无效代码或失败可能减少实际启动。先plan再run，按评价量和API期限设置窗口；执行器会预留当前任务的完成余量，可能在截止前停止启动新任务。

`solve_seed=501`、`instance_timeout=30`、H源、评分归一化和同分规则先保持不变。需要改变这些科研条件时，应单独制定新协议，不靠修改普通参数绕过。

## 六、查看进度、安全暂停与恢复

```sh
.venv/bin/python -B experiments/tier2/manage.py status --run-dir runs/learn-ind-01
.venv/bin/python -B experiments/tier2/manage.py stop --run-dir runs/learn-ind-01
```

stop只发暂停请求，当前候选的生成、完整评价认证和账本提交仍会完成。等待status显示`phase=paused`且`writer_lock_present=false`，才恢复：

```sh
.venv/bin/python -B experiments/tier2/manage.py resume --run-dir runs/learn-ind-01 --allow-api --background
```

非API实验不需要`--allow-api`。前台Ctrl-C同样请求边界暂停。已经完成的短实验不能再暂停/恢复；这是正常保护。

|`phase`值|中文含义|下一步|
|---|---|---|
|`prepared`|已冻结，尚未启动|使用run。|
|`launching` / `running`|正在启动/运行|查看状态或请求stop。|
|`paused`|已安全暂停|确认无锁、身份匹配、仍在原窗口内后resume。|
|`completed`|计划全部执行结束|汇总；不等于所有候选都有效。|
|`expired`|窗口余量不足，保留部分结果|汇总，不自动重置截止或重开剩余槽位。|
|`stopped`|保护停止|读取Stop.json；未知状态不能自行清锁重试。|

首次run建立截止时间，暂停和恢复都不重置。断电或强杀可能留下未知请求、任务预留或锁，不等同安全暂停。配置、提示、数据、H或已绑定执行源码发生改变时，不能恢复原实验。**新参数＝新配置副本＋新实验目录**；不要在prepare后改同一份绑定配置。

后台脚本自行运行、记账并结束，不依赖模型持续监控。保持电脑有电且唤醒；临时防空闲休眠不保证合盖、断电、注销或重启期间继续计算。


|---|---|

## JSON参数

与现有项目相同使用JSON，provider直接复用`ProviderConfig`字段。薄封装增加`schema=experiment-operations-v1`声明，避免把旧专用协议当可变配置。`check`/`plan`校验和解析但不建run、不求解、不创建API客户端。`prepare`只复制/冻结文件与模板，也不求解。

|类别|字段|用途|
|---|---|---|
|实验|`type, question, space`|`fixed`固定策略、`rules`规则族、`pair`配对、`ind`独立生成、`evo`演化、`cross_ab`固定父代交叉对照；空间为h01或ten_h。|
|数据|`dataset.files`或`dataset.protocol`，`dataset.role`|显式文件列表，或已有协议中的实例清单；engineering/train/confirmation分别表示工程/训练/确认。列表顺序参与身份。|
|H|`H_source`|已封存10H JSON；h01可用[0,1]，ten_h可用[0..9]。|
|固定U/P0|`strategies`、`p0`|每项唯一id及alpha/member/code_file之一。H01仅接受互补权重；通用静态双成员可直接提供合法U代码文件。|
|既有规则族|`rule_filter.tau/alpha_before/alpha_after`|原21规则族的子集；tau=.25/.5/.75，alpha=0/.5/1；空filter为完整21；不扩展新规则。|
|搜索|`search_seed, candidates, population_size, generations, cross_per_generation, mutate_per_generation, cross_parents`|IND候选数；EVO显式P0规模及每代CROSS/MUTATE。h01保持N5/5交叉父代；ten_h可配置2–5交叉父代且不超过N。|
|固定父代AB|`parent_pairs, repeats`|只接受已认证的历史自由P0，两组同一对同顺序；必须完整匹配train21/H/LB，不能拿B2五静态P0冒充。|
|提示|`prompt_overrides`|可选I1/CROSS/MUTATE模板文件；恰有一个`{{BASE_PROMPT}}`。默认为空，逐字复用原模板。AB拒绝override以保持唯一反馈差异。|
|API|`api_mode, real_requests_authorized, provider`|disabled/mock/real分别表示禁用/模拟/真实；真实调用要求配置true和run/resume显式--allow-api；凭据只从指定环境变量取，不自动读其他工作区的凭据文件。|
|请求规模|`api_attempt_cap, per_candidate_attempt_cap`|每逻辑候选最多2尝试；失败不补员。退避目前内部固定2秒，协议保存完整transport_config。|
|评价|`solve_seed=501, instance_timeout=30`|当前入口强制保持，不能改JSON绕过科学协议。完整首解复检、动作/归一化/正常退出规则非CLI参数。|
|窗口|`window_seconds`|最多43200秒；首次run持久化；新任务预留最坏请求+求解余量。暂停/恢复不重置。|
|工程模拟|`mock_delay_seconds`|仅mock+engineering，0–2秒，用于离线控制验收；不进入真实请求配置。|
|CLI参数|`--config, --run-dir, --allow-api, --background, summary --write`|配置/目录/明确API启动/脱离启动控制进程/本地汇总；不是科学调参开关。|

plan展示最坏物理评价量，含P0。缓存只在同一个新run内按U AST和冻结上下文复用，逻辑槽位仍计数；没有自动历史缓存导入。P0不会神奇免费继承旧Fitness。数据改为train21时其P0成本和新增成本都会增加，先看plan再run。

### 模型与请求参数

|`provider`中的字段|中文含义|修改时要注意|
|---|---|---|
|`endpoint` / `protocol`|请求地址/接口协议|使用同一服务支持的地址与协议，不凭名称假定兼容。|
|`model` / `expected_response_model`|请求模型/预期回传模型标识|换模型时一起核对；回传身份不符不能静默接受。|
|`api_key_env`|存放密钥的环境变量名称|这里写变量名，不写密钥值。|
|`max_output_tokens`|单次输出Token上限|限制输出长度，不等于总候选预算或已验证费用上限。|
|`max_prompt_bytes`|提示内容的字节数上限|字节数不是Token数。|
|`temperature` / `reasoning_effort`|采样温度/推理参数|示例为null；是否可设置取决于服务和模型，不支持的参数不要随意添加。|
|`connect_timeout` / `read_timeout` / `total_timeout`|连接/读取/请求总超时|这是API请求期限，不能和单实例T30求解期限或总运行窗口混淆。|
|`stream_response`|是否流式回传|示例为false，第一次先保持现有设置。|

### 常见错误怎样处理

|现象|先检查什么|
|---|---|
|check提示JSON解析失败|是否误写注释、漏引号、漏逗号或末尾多逗号。|
|prepare拒绝已有目录|它保护原记录；查看已有实验，下一次另取新名称，不删除目录来绕过。|
|真实API启动被拒绝|配置是否true、命令是否有--allow-api、当前终端是否设置了对应环境变量。不要打印密钥排查。|
|模型或配置身份不一致|是否改过prepare时绑定的文件，或回传模型不符；保留证据，不修改旧协议假装匹配。|
|很快显示expired|剩余窗口是否足够容纳请求及完整候选评价；执行器会预留余量，不只等到最后一秒。|
|完整Fitness为null|查看失败类型及逐实例记录；不取成功前缀重新算正常成绩。|
|断电后残留锁/未知请求|按未知状态保留；不能直接删除锁、清预留、重复发送或求解。|

### 环境、模板和输出快照

prepare保存`Resolved_config.json`、`Protocol.json/.sha256`、`Tasks.json`、H/Parents、输入副本、source_files/protected_files、Git提交、Python及模板示例。实际每次提示位于`prompts/`，首份完整响应位于`responses/`，每次尝试及回传位于`API_attempts.json`和`wire_responses/`。

模板示例不是随机选定的最终父代；真实提示按已记录父代现场渲染保存。IND不含P0/历史；默认CROSS/MUTATE不含成绩；只有cross_ab的B添加完整绑定成绩。新提示文件或源配置改动会导致旧run恢复被拒绝。建议先复制示例为自己的配置，之后不要改这个已绑定文件；换配置就用新目录。

## 控制与异常

`stop`请求候选边界暂停，当前生成和完整评价认证后落盘才退出。SIGINT/SIGTERM也只设置边界停止标记；不是强杀命令。确认checkpoint.phase=paused且锁已解除才resume。每次结束回执另存`end_receipts/`，旧暂停请求保留在`control/`，resume只确认已处理序号。

窗口到期是expired/partial，不能自动续期。断电、SIGKILL或未提交任务可能留下未知reservation/锁；入口明确拒绝自动清理或重复请求/求解。连续3个逻辑传输失败停止。普通已认证求解超时是候选无效，可继续其他预定候选；完整Fitness=null。

后台使用原有detach函数：与启动终端分离的会话、文件日志、忽略终端挂断信号，临时防空闲休眠任务绑定执行进程。工程验收验证“启动命令进程退出后继续”和暂停恢复；不承诺Mac合盖、休眠、注销、重启、App关闭时所有系统行为。电脑仍须有电且保持唤醒。无需模型持续监控；脚本自己记录、汇总和结束。

search_seed控制EVO父代抽样；IND只记录重复身份，模型请求不传seed。不同重复编号不保证严格随机配对，改变求解seed也不是新的搜索重复。

新入口只有单run写锁，不提供多个真实API campaign的账户级并发协调或跨run费用上限。不要把启动多个独立目录理解为共享同一候选预算。真实provider服务当前是否可用本轮未请求验证；Mock不能保证服务可用或模型输出质量。

## 结果口径

- `logical_generation`：开始过的逻辑生成任务；失败占槽，不是有效代码数。
- `API_attempts`：实际尝试/保守预留次数，含重试和未知状态；不等同完整响应。
- `complete_responses`：首份完整响应，不因代码无效再生成。
- `certified_strategies`：完整实例集评价有效的任务数，缓存复用可以贡献任务数；不等同新增物理求解数。
- `Per_instance.csv`标明`complete_candidate_valid`；失败的成功前缀仅为明细，不参与正常完整Fitness。
- `new_champion`仅指新增生成子代；固定评价另有`fixed_evaluation_champion`；已见最好包含P0，不能把继承P0算新发现。
- Token已知值和未知尝试分别列；实际币种/扣点未核实则null，无价格认证前置门禁。

`summary --write`输出`results/Summary.md`（可直接贴回讨论）、JSON、Candidates/Per_instance/Best_so_far/Evaluation_costs.csv。摘要是确定性事实，不调用LLM、不替用户决定后续研究。对历史run只读已有报告，缺少标准摘要时指向原专用报告入口，不伪造通用转换。
