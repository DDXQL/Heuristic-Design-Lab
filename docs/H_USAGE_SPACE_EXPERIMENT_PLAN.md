## 1. 研究问题与分离对照

主要问题：在相同固定H、七状态、v2.2提示、搜索算子、共享SELECT初始化和请求预算下，演化允许双成员组合，是否更容易找到更好的完整排程策略，且新增计算成本可接受？

主要配对：S-score（仅SELECT）与S-mix（SELECT/MIX）。相同父代时唯一提示许可差别仍为allowed_modes，不能只给S-mix增加评分/组合鼓励。两组都允许常量、条件、成员评分等表达，不按代码外观强行分类，不强迫组合。

第二个问题“v2.2是否提高生成评分/动态权重的概率”需要另一个独立提示对照：在相同允许模式内比较v2.1/v2.2。不能把它与开放MIX的效果混在一个二组差异中；必要时后续登记2×2实验，另报预算。

动态权重的独立收益也需要在候选发现后另登记固定成员对/固定权重对照。只比较S-score/S-mix不能把全部差异解释成权重自适应收益。

## 3. 冻结项和未来资源登记

执行前分别固定：研究H批准与代码键、数据清单/划分、源码和提示fingerprint、模型/采样、种子清单、N/代数/每代槽位、初始化失败规则、主评价与诊断期限、每组请求/token及总预算、数据选择规则、唯一执行者和账本目录。

建议正式比较至少5个配对种子；具体种子、代数、预算在正式登记中确定，不在本草案填入可执行值。共享SELECT初始化可减少起点差异，但组合只能在演化出现；因此结论限定为该起点和预算条件。若研究组合初始化，应另登记实验，不悄悄改共享起点。

当前UsageConfig真实模式硬限制一个seed/N5/init20/一代10/总40，不能直接拿它运行本草案的多种子研究。未来需要新的独立协议/入口，保留旧配置解释；本阶段不改这个限制、不建立实验运行目录。

请求失败、重复、非法和运行失败都占槽位，不追加到两组有效数相同；初始化不足预定N则记录失败，不补手写候选/旧U。H缺少批准或预算未登记时不得调度真实研究请求。

## 4. 主要指标和行为解释

效果：逐实例Cmax、Cmax/LB；共享P0和最终最优/种群均值；按seed配对差及胜/平/负，报告训练选择造成的偏差。计算成本：全部请求/token/服务时间、求解/复检/诊断、h调用和组合处理，明确失败成本缺失。等请求预算不等于等算力。

生成质量：全部响应的解析/接口/运行失败率、AST重复率、完整有效候选数；有效候选中解码行为、动作/排程重复分别统计，写明分母与观察范围。训练行为hash包含原vector，不能把它直接当argmax/排程等价hash；同fitness不等价。

实际机制：生成、完整有效、最终保留三个阶段分别报SELECT/MIX、真正双成员占比、固定成员对/动态成员对、固定权重/动态权重、模式变化、常量/单选/退化。MIX单正项合法但不是双成员；两成员同动作偏好不证明组合互补。分支更多、切换更多、成员更多不作为目标。

如果S-mix获胜候选只执行SELECT，不将差异归因于实际双成员组合；如果没出现有效双成员，应区分未生成、非法、运行失败或未被保留，不直接否定空间。完整排程fitness绝不作为逐状态成员正确标签。
