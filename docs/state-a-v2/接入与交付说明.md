## FJSP页如何接入

1. 采用本轮交付提交，导入 `fjsp.routing.construct_state_a`，U统一用 `core.routing_state_a` 解析、编译和生成提示。冻结H代码、编号与原动作输入，不另改状态模块。
2. 该入口复用原追加式调度、动作枚举和首个最大分数并列规则。返回 `result.schedule.makespan` 为原始成本，`result.reference` 为LB_v5，`result.score` 为相对差距，`result.score_direction='min'`；LB无向上取整。
3. 新搜索必须最小化 `result.score`，在新目录、新协议运行；旧负Fitness最大化代码不能直接接收新分数。缓存绑定新的状态、U、评价器和参考值身份。

## TSP页如何接入

1. 采用同一交付提交，导入 `tsp.routing.construct_state_a`，传入已冻结的正LKH参考长度 `reference`，U使用同一公共模块。缺少参考值直接失败，不运行NN或LKH来补齐。
2. 固定起点0，原H的5个动作输入及其sqrt(2)尺度不变；U的需求和动作增量采用dmax。最高H原分数胜出，精确同分选最小城市编号。
3. `result.length` 包含最后闭环；`result.reference` 保存所传参考，`result.score` 为相对差距，`result.score_direction='min'`，按最小化接入新评价器。闭环不进入状态历史。
4. LKH版本、预算、距离定义和数据参照文件由评价协议页冻结；本轮没有生成LKH参考，也没有改写历史NN评分。
