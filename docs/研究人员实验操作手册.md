# 研究人员实验操作手册

从 `configurations/experiments/` 选择一个 JSON 样例。可以在 Mac 编辑和预检，从实验室电脑通过 UU 登录集群后，在 R15 新部署目录启动。Slurm 接收提交后负责运行，终端可以关闭。

| 样例 | 用途 | 启动条件 |
| --- | --- | --- |
| [tsp-502.json](../configurations/experiments/tsp-502.json) | TSP 双层 U 与 EoH，种子 502 | 在 `research.reference` 指定已生成的 D06 LKH train20 参照，或使用 R15 目录已绑定的同一参照 |
| [fjsp-503.json](../configurations/experiments/fjsp-503.json) | FJSP EoH，种子 503 | train21 随发布包提供。FJSP U 的原冻结执行器暂未接入成功返回口径 |
| [obp-501.json](../configurations/experiments/obp-501.json) | OBP 双层 U 与 EoH，种子 501 | U 仍需要 H401 筛选并正式冻结的 10H 文件。可另存一份仅保留 EoH 的配置并使用新名称 |
| [slurm-no-api-smoke.json](../configurations/experiments/slurm-no-api-smoke.json) | Slurm 上的无 API 流程检查 | 用合成候选及合成评价，使用隔离的临时账户账本 |

新批次使用新的 `name`。在 `research.runs` 写一到两个方法与种子的组合，每个组合独立初始化。当前支持 `u` 和 `eoh`。样例中的 `null` 资产路径会采用该组已有的默认绑定。TSP 可复用已取回的 `tsp-reference.json`，或填集群上现有文件的绝对路径。入口会检查参照版本、参数、实例顺序和路线复算结果。

## 1. 预检、启动、查询和导出

拿到 R15p3 发布 ZIP 和校验文件后，在集群上传目录先核对 SHA-256，再解压到独立目录。下面的命令要求目标目录尚未创建。

```bash
HDL_ZIP=triad-candidate-runtime-20261119-r15p3.zip
HDL_HOME=/public2/home/qiuqian/hdl-deploy/triad-candidate-runtime-20261119-r15p3
sha256sum -c "$HDL_ZIP.sha256" && mkdir "$HDL_HOME" && unzip -q "$HDL_ZIP" -d "$HDL_HOME"
cd "$HDL_HOME"
```

在集群上的 **R15 新部署目录** 执行。以下以 TSP 的样例为准。Mac 做预检时，将 `HDL_P` 换成本机已安装依赖的 Python 路径。

```bash
HDL_P=/public2/home/qiuqian/hdl-envs/portable-v2/bin/python
HDL_CFG=configurations/experiments/tsp-502.json

"$HDL_P" -s -B tools/experiment.py prepare "$HDL_CFG"
"$HDL_P" -s -B tools/experiment.py run "$HDL_CFG" --approve
"$HDL_P" -s -B tools/experiment.py status "$HDL_CFG"
"$HDL_P" -s -B tools/experiment.py export "$HDL_CFG" --out "$PWD/tsp-502-results.zip"
```

- `prepare` 检查文件、预算及参数。两组均显示 `pending: []` 表示资产预检通过。这一步不请求模型、求解或提交 Slurm。
- `run --approve` 启动本批，明确允许配置所列上限内的模型发送及训练评价，并确认共享账户没有其他生成者。看到 `submitted: true`、搜索作业 ID 和首个审核作业 ID 后，Slurm 已接管。R13 仍占用同一账户时，入口会在提交前停止。
- `status` 读取作业号、候选进度、发送统计、最优训练 J 和停止原因。需要确认排队位置时可对作业号运行 `squeue -j 作业ID`。
- `export` 把已落盘的结果压缩成 ZIP，包含各组状态、候选与请求表、曲线和已生成的冠军记录。可在实验室电脑用 SCP 取回这个 ZIP。等待时限接续期间，仍在运行的成员会等稳定导出后再纳入。

## 2. 修改参数

- `research` 记录问题、方法、种子、训练数据、冻结 H、状态方案、初始化上限和候选计数。当前真实批次每个种子目标是 1000 个成功返回的演化候选。正常返回的无效、重复和评价失败候选也计数。空响应和截断响应依据配置的 `empty` 与 `truncated` 处理。冠军按最小训练 J、同分按固定 ID 选择。正式验证或测试使用独立流程。
- `execution` 控制 Slurm CPU、内存、单段时限、整个时间窗口、最多分段数、账户排他期限和自动释放选项。API 总并发当前为 1，两份搜索可同时排队并独立提交评价。API 超时、队列等待、有限重试和连续失败阈值也在这里设置。阈值 `0` 关闭连续失败停组，仍受预算和租约限制。
- 样例给每个种子最多 20 次初始化和 1100 次演化请求预留，演化预留包含已发送、确认未发送及发送状态未知的记录。发送次数另计。TSP 两组合计预留上限为 2240。H 构建成本单独登记。收到已确认终态 HTTP 520／522／524 后，原槽不重放，预算有余时从新槽补齐。
- 提交后保留原 JSON。修改研究或运行设置做新批次时，复制文件并换一个 `name`。旧的 R13 批次继续按原冻结版本和 1000 次尝试口径管理。

## 3. 正常续跑和恢复示例

接近 Slurm 时限时，搜索在候选边界保存，审核作业核对原检查点和账本后提交下一段。最后一段会自动写训练结果。如果请求预留用完，状态会报告未完成及已取得的候选数。按样例设置，已干净结算的终止批次会在导出后释放自己的账户占用。

例如需要暂时让出计算资源时，在搜索作业都已开始后主动暂停一次。

```bash
"$HDL_P" -s -B tools/experiment.py pause "$HDL_CFG"
"$HDL_P" -s -B tools/experiment.py status "$HDL_CFG"
"$HDL_P" -s -B tools/experiment.py resume "$HDL_CFG"
```

等状态显示 `operator_paused` 后再运行最后一条。它沿用本批原授权、累计请求、时限和检查点。若共享 STOP、发送状态未知、Slurm 提交回执不清、已有下一段，或已用完授权，入口会保留原记录并拒绝重放。查看状态输出指向的作业和审核异常，核对后再处理。

## 4. 上线前现场验收

本地已用 Mock 走完整个 CLI 流程，包括两组正常分段接续、主动暂停后恢复、达到预算上限报告未完成及 ZIP 导出。以下现场步骤待另行批准。

1. **调度依赖。** 使用[现有调度探针](长实验自动续跑与结果导出.md#4-离线验收)验证计算节点可提交依赖作业，检查 `child.passed`。
2. **共享目录互斥。** 在计划使用的节点上运行下面的双进程检查。若计划跨节点执行，申请两节点且每节点一个进程。检查 `reports/r15-fs-smoke/<作业ID>/fs-pass-*.json`。

   ```bash
   sbatch --parsable --partition=128C_02 --account=wz --qos=normal \
     --nodes=2 --ntasks=2 --ntasks-per-node=1 --cpus-per-task=1 --mem=1024M \
     --time=00:05:00 tools/experiment_fs_probe.sbatch "$HDL_P"
   ```

3. **分段续跑。** 用 `slurm-no-api-smoke.json` 执行同一组 `prepare`、`run --approve`、`status`、`export` 命令。该样例把 Mock 回复间隔设为 20 秒，用 30 分钟作业时限和 27 分钟收尾阈值触发分段。验收时确认至少一次时限保存、自动接续及最终 ZIP，槽位、候选数与账本连续。这个配置不读取真实凭据，也不执行真实评价。

三项通过后，再单独确定有限的真实 API 与真实训练评价预算，做一次小规模端到端验收。正式 R15 批次保留 1000 个成功返回的目标，有限验收需单独记录。
