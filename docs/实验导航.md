## TSP

复制 [tsp-502.json](../configurations/experiments/tsp-502.json)，或用菜单选 `tsp`。冻结资产在 `preparations/triad/tsp/`，需要 train20、U 用的 10H 和 D06 参照。R15p3 现场包已保存 `preparations/operations/tsp-reference-r15.json`。新部署要显式引入同一核验资产。问题实现见 [TSP](../code/heuristic_design/problems/tsp)。用根页的 `prepare → run → status → export`，训练外评价单独执行。

## FJSP

复制 [fjsp-503.json](../configurations/experiments/fjsp-503.json)，或在菜单选择 `fjsp/u` 或 `fjsp/eoh`。使用 train21 和 [FJSP 适配](../code/heuristic_design/problems/fjsp)。U 使用原冻结 10H、方案 A v3、N5 和 20 个初始化预留。研究评价仍用完整 train21 和 LB_v5。R15 每种子串行评价并可跨种子并发。`run_frozen.py` 用于原尝试口径和旧检查点。

## OBP

直接使用 [obp-eoh-501.json](../configurations/experiments/obp-eoh-501.json)可独立预检 EoH。U 用 [obp-501.json](../configurations/experiments/obp-501.json)或菜单。训练集是 train96，EoH 仍使用 N10 严格有限父代策略。U 和固定 H 等 H401 冻结 10H 后绑定。装箱动作和共同状态适配见 [OBP 状态](../experiments/triad/obp_state_preset.py)。

## 新版无 API 验收

在已解压的新版本根目录运行。使用独立目录中随包提供的 Mock 配置。以下命令供批准现场验收后使用。

```bash
P=/public2/home/qiuqian/hdl-envs/portable-v2/bin/python
MOCK=configurations/experiments/slurm-no-api-smoke.json
"$P" -s -B tools/experiment.py prepare "$MOCK"
"$P" -s -B tools/experiment.py run "$MOCK" --approve
"$P" -s -B tools/experiment.py status "$MOCK"
"$P" -s -B tools/experiment.py export "$MOCK" --out "$HOME/r15-mock-results.zip"
```

这份配置用于单种子调度冒烟测试。是否实际接续，以作业和审核回执为准。三种子验收还需每个种子达标并各自导出结果。2026-11-21 核查时，`128C_02` 只有 `node15`，双节点探针需选有至少两个可分配节点的授权分区。跨节点互斥的通过证据为不同节点各自产生的 `permit-pass-*.json`。

新版三种子验收使用 [r15p5-site-no-api.json](../configurations/experiments/r15p5-site-no-api.json)。导入 D06 参照后，将上述 `MOCK` 换成该配置，导出时使用新的 ZIP 文件名。每个种子要达到 20 个成功返回，最多 24 个演化请求预留。检查 `status` 的 `outcome=scientific_complete`、三组导出和至少两段作业回执。

已有 D06 参照可按[部署步骤](R15真实验收与六组.md#部署和回退)校验后复制到新版。真实候选评价和账户吞吐分别按[验收与回退](../DECISIONS.md#验收与回退)验证。
