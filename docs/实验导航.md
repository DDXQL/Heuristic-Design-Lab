# 实验导航

## 能力矩阵

“接入”表示开发主线可预检并形成作业。三种子与新版 API 并发目前仅离线验收。历史运行证据和新版本分别记录。

| 问题 | 双层 U | EoH | 固定 H | 传统 HH |
| --- | --- | --- | --- | --- |
| [TSP](#tsp) | 已接入。冻结 10H、train20、D06 | 已接入，train20、D06 | 独立评价入口，使用同一资产 | 尚未接入 |
| [FJSP](#fjsp) | 历史冻结执行器可用，R15 未接入 | 已接入，train21 | 独立入口，复用已核验的 10H 结果 | 尚未接入 |
| [OBP](#obp) | 已接入，缺 H401 正式 10H | 已接入，train96 预检通过 | 独立入口，缺 H401 正式 10H | 尚未接入 |

三个问题共用 [TSP/FJSP/OBP 适配](../experiments/triad/problems.py)、[评价](../experiments/triad/evaluation.py)和[运行入口](../tools/experiment.py)。U 使用 [U 演化](../code/heuristic_design/core/evolution_v1.py)，EoH 使用[原生接入](../deploy/eoh-baseline/eoh_gap.py)。固定 H 先通过 [assets.py](../experiments/triad/assets.py) 的 `fixed-plan --config` 检查该问题的低层 U 配置。确认来源及预算后再用同脚本的独立评价入口。固定 H 无模型请求预算。传统 HH 暂无可提交的配置。

## TSP

复制 [tsp-502.json](../configurations/experiments/tsp-502.json)，或用菜单选 `tsp`。冻结资产在 `preparations/triad/tsp/`，需要 train20、U 用的 10H 和 D06 参照。R15p3 现场包已保存 `preparations/operations/tsp-reference-r15.json`。新部署要显式引入同一核验资产。问题实现见 [TSP](../code/heuristic_design/problems/tsp)。用根页的 `prepare → run → status → export`，训练外评价单独执行。

## FJSP

复制 [fjsp-503.json](../configurations/experiments/fjsp-503.json)，或选择 `fjsp/eoh`。使用 `preparations/eoh-gap/train21.manifest.json` 和 [FJSP 适配](../code/heuristic_design/problems/fjsp)。EoH 的预检和启动用根页命令。U 的历史冻结入口是 [run_frozen.py](../experiments/common/run_frozen.py)。固定 H 使用 [FJSP 基础 U 配置](../configurations/six-groups-20261116/fjsp-u.json)核对现有结果后导入。

## OBP

复制 [obp-501.json](../configurations/experiments/obp-501.json)，或用菜单选 `obp`。只做 EoH 时在 `research.runs` 保留 EoH。训练清单在 `preparations/triad/obp-official-20261115/train.manifest.json`。U 和固定 H 需要按 [H401 构建入口](../experiments/triad/assets.py)生成并冻结的 10 条 H。取得已核验资产后填 `research.frozen_h`，再预检。装箱动作和共同状态适配见 [OBP 状态](../experiments/triad/obp_state_preset.py)。

## 新版无 API 验收

在已解压的新版本根目录运行。使用独立目录中随包提供的 Mock 配置。以下命令供批准现场验收后使用。

```bash
P=/public2/home/qiuqian/hdl-envs/portable-v2/bin/python
MOCK=configurations/experiments/slurm-no-api-smoke.json
"$P" -s -B tools/experiment.py prepare "$MOCK"

sbatch --parsable --partition=128C_02 --account=wz --qos=normal \
  --nodes=2 --ntasks=2 --ntasks-per-node=1 --cpus-per-task=1 --mem=1024M \
  --time=00:05:00 tools/experiment_fs_probe.sbatch "$P"

"$P" -s -B tools/experiment.py run "$MOCK" --approve
"$P" -s -B tools/experiment.py status "$MOCK"
"$P" -s -B tools/experiment.py export "$MOCK" --out "$HOME/r15-mock-results.zip"
```

双节点作业应产生两份 `permit-pass-*.json`。Mock 批次需完成两段或更多并自动导出，确认计算节点的依赖提交和真实时间保护。已有参考文件可从 R15p3 部署目录只读复制到新版的 `preparations/operations/tsp-reference-r15.json`，菜单会识别它。首批真实候选评价用批准的有限预算。账户吞吐另按 [DECISIONS](../DECISIONS.md#验收与回退) 逐级验证。
