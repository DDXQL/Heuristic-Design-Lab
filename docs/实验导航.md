## 新版无 API 验收

在已解压的新版本根目录运行。使用独立目录中随包提供的 Mock 配置。以下命令供批准现场验收后使用。

```bash
P=$HOME/hdl-envs/portable-v2/bin/python
MOCK=configurations/experiments/slurm-no-api-smoke.json
"$P" -s -B tools/experiment.py prepare "$MOCK"
"$P" -s -B tools/experiment.py run "$MOCK" --approve
"$P" -s -B tools/experiment.py status "$MOCK"
"$P" -s -B tools/experiment.py export "$MOCK" --out "$HOME/r15-mock-results.zip"
```

这份配置用于单种子调度冒烟测试。是否实际接续，以作业和审核回执为准。三种子验收还需每个种子达标并各自导出结果。2026-11-21 核查时，`128C_02` 只有 `node15`，双节点探针需选有至少两个可分配节点的授权分区。跨节点互斥的通过证据为不同节点各自产生的 `permit-pass-*.json`。

新版三种子验收使用 [r15p5-site-no-api.json](../configurations/experiments/r15p5-site-no-api.json)。导入 D06 参照后，将上述 `MOCK` 换成该配置，导出时使用新的 ZIP 文件名。每个种子要达到 20 个成功返回，最多 24 个演化请求预留。检查 `status` 的 `outcome=scientific_complete`、三组导出和至少两段作业回执。

已有 D06 参照可按[部署步骤](R15真实验收与六组.md#部署和回退)校验后复制到新版。真实候选评价和账户吞吐分别按[验收与回退](../DECISIONS.md#验收与回退)验证。

## 现行 U 研究协议

本节是当前 U 研发和比较的协议入口。研究决定见 [DECISIONS.md](../DECISIONS.md)，具体批次以原 `Protocol.json`、输入哈希和正式回执为准。研发源码基点为 [`22050e2`](https://github.com/DDXQL/Heuristic-Design-Lab/commit/22050e2)。这里的 U‑2 指现行使用 CROSS 与 MUTATE 的双层 U。9 月方案仅作历史参考。

| 环节 | 正式规则 |
| --- | --- |
| 冻结 H | 每个问题的 U 比较共用同一套、同一顺序的 10 条动作评分规则。TSP 和 FJSP 使用现有冻结库，OBP 使用正式 H401。三个 U 种子各自搜索 U，共享 H。H 的构建成本单列。用冻结文件与 `Protocol.json` 核对顺序、程序标识和哈希。见 [输入绑定](../experiments/triad/problems.py)。 |
| 共同状态与 U 接口 | 方案 A v3 提供 10 个标量、4 组按 H 排列的实际提交历史及对应可用性标记。最近统计取全局最近最多 10 次提交，缺失值根据标记处理。每个实例重新开始记录。U 只读公开状态，`use_heuristics(state)` 返回一个内置整数 H 编号。允许恒定选择同一 H。禁止混合评分、调用其他 H、预演或读取未来信息。见 [状态约定](../code/heuristic_design/core/state_a_v3.py)、[接口校验](../code/heuristic_design/core/routing_state_a_v3.py)。 |
| 动作执行 | 每一步先观察、再选一条 H、只用该 H 给合法动作评分，固定构造器选最高分并在执行后写入历史。TSP 从城市 0 开始，同分取小编号，最后强制闭环。FJSP 枚举各作业下一工序及允许机器，按两者就绪时间追加，同分按冻结枚举顺序。OBP 依到达顺序，在预分配箱中只看当前物品及当前可行箱，同分按箱号。见 [TSP](../code/heuristic_design/problems/tsp/routing.py)、[FJSP](../code/heuristic_design/problems/fjsp/routing.py)、[OBP](../experiments/triad/problems.py)。 |
| 初始化与种群 | 正式模板使用 501、502、503 独立搜索。每个种子的初始化提示给固定 H 资料，独立生成 U。最多预留 20 次初始化请求，收集 5 个完整有效且语法树不同的 U。未满 5 个则初始化未完成。初始化及代内操作见 [R15 运行适配](../experiments/triad/runtime.py)。 |
| 父代与演化 | 每代冻结当前 5 个父代。轮到每位父代时，CROSS 用该父代和一个从其余成员均匀抽取的不同搭档，MUTATE 只用该父代。按父代交替安排一次交叉和一次变异，每代共 10 个位置。整代结算后合并有效父子，按训练 J、固定候选 ID 留前 5 名。保存随机状态和代内计划，续跑原位置。见 [代内计划](../code/heuristic_design/core/evolution_v1.py)、[CROSS 与 MUTATE](../code/heuristic_design/core/operators.py)、[保留规则](../code/heuristic_design/core/search.py)。 |
| 预算与计数 | 做法 B 每种子以 1000 个成功返回的演化候选为目标，正式模板有 1100 次演化请求预留上限。正常提取到候选后的语法、接口、重复和评价失败照计。传输失败、空响应和被排除的截断响应不计入 1000。初始化、H 构建、物理发送、完整有效评价及求解开销分别报告。触及物理上限且未达标时报告未完成。见 [候选计数策略](../experiments/triad/candidate_policy.py)。 |
| 训练评价 | TSP 用 train20 和冻结的 D06 LKH 参照，FJSP 用 train21 和 LB_v5，OBP 用 train96 和 R_code。每个完整实例按 `(求解成本 − 参照) / 参照` 计分，训练 J 是全训练集平均，越小越好。T30 要求同一实例的首解和独立复核在 30 秒内交回一致结果，缺一例则候选无有效训练 J。见 [评价器](../experiments/triad/evaluation.py)、[计分](../code/heuristic_design/core/state_a.py)。 |
| 冠军冻结与外评 | 在全部已结算且完整有效的训练候选中，先取最小训练 J，同分取固定 ID。最后一代即使在达标时未满，其中完整有效的候选仍可参选。训练达标后冻结程序、运行协议和身份。用预定的留出实例及独立参照评价已冻结冠军，保留逐种子和逐实例结果。留出成绩不得参与选优。见 [训练导出](../experiments/triad/runtime.py)、[冻结外评](../experiments/triad/post_evaluation.py)。 |

### U-2 核验结论

**U‑2 可作为可靠的现行方法对照。** 已采用规则与核验到的实跑结果一致，没有发现需要撤销既有结果的实现错误。TSP 三个 U 种子均达到 1000，使用同一顺序的 10H。与当前 EoH 三个种子使用相同的训练实例、参照和记录中的模型标识。六个冠军的归档哈希与各自 confirm60 外评相符。FJSP‑U 503 的完整断点可以复算出相同父代、随机状态、代末保留结果和冠军。它有 1006 条演化记录，其中 1000 条成功返回，另外 6 条为传输失败。TSP 本地归档支持核对训练计数和冠军，完整逐代父代核查以原集群记录为准。OBP‑U 当前缺完赛证据。见 [TSP 外评记录](../reports/tsp-confirm60-nine-20261124/seed-results.csv)、[本机归档索引](../PROJECT_MAP.md#版本库与实验归档)。

论文中要保留两个比较边界。第一，等 1000 个成功返回只对齐了候选返回口径，未对齐完整评价数或求解成本。TSP 三个 U 种子各有 546、651、649 次完整且不重复的训练评价，EoH 对应为 997、994、1001 次，这些数含初始化。第二，U 和 EoH 的搜索对象、种群规模和去重方式不同。当前结果可比较两个方法的整体效果。若要归因到 U 的算子改动，应单独做配对的 U‑2/U‑5 对照。见 [候选与评价开销](../reports/tsp-u-mechanism-20261126/candidate-accounting.csv)。

### 项目 EoH 与论文五算子

现行项目的 EoH 直接演化动作评分规则 H，采用 I1 初始化，随后按 **E1 → E2 → M1 → M2** 循环。E1/E2 按排名倒数权重有放回抽两条父代规则，M1/M2 取一条。论文还提出 M3 去冗余，并在消融实验中给 E1/E2 配置五父代。论文中的 E1 强调提出与父代不同的思路，E2 强调借共同思路扩展，M1 和 M2 分别修改规则与参数。项目正式结果应表述为四算子 EoH 实现。新页面处理五算子如何作用于 U，如需补五算子 EoH 对照，应另立配置和结果身份。见 [项目算子序列](../code/heuristic_design/problems/tsp/eoh_single.py)、[R15 EoH 接入](../deploy/eoh-baseline/eoh_gap.py)、[原生父代抽样](../code/llm4ad/method/eoh/population.py)、[EoH 论文第 3.4 与 4.3 节](https://arxiv.org/html/2401.02051)。
