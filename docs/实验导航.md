## TSP

正式三种子选上表中的方法，也可复制 [tsp-502.json](../configurations/experiments/tsp-502.json)做单种子对照。冻结资产在 `preparations/triad/tsp/`。训练需要 train20、U 的 10H 和 D06 参照。现场包提供 `preparations/operations/tsp-reference-r15.json`，新部署应复用已核验资产。问题实现见 [TSP](../code/heuristic_design/problems/tsp)。正式外评 confirm60 使用独立 D06 和已冻结的冠军，见[外评配置示例](../configurations/experiments/r15-tsp-eoh-confirm60-example.json)。

## FJSP

正式三种子选上表中的方法，单种子用 [fjsp-503.json](../configurations/experiments/fjsp-503.json)。使用 train21 和 [FJSP 适配](../code/heuristic_design/problems/fjsp)。U 使用原冻结 10H、方案 A v3、N5 和 20 个初始化预留。评价使用完整 train21 和 LB_v5。历史尝试口径保留 `run_frozen.py` 和原检查点。需要留出集时在 `research.holdout` 写入正式清单。

## OBP

用上表的正式配置启动三种子，或用 [obp-eoh-501.json](../configurations/experiments/obp-eoh-501.json)独立预检 EoH。训练用 train96 和 R_code。采用原生准入的 EoH 使用 `native_EoH`。U 和固定 H 配置应在预检时读到正式 H401 冻结 10H。现场 H401 已核验，新部署应按原哈希绑定。装箱动作和共同状态适配见 [OBP 状态](../experiments/triad/obp_state_preset.py)。

## 运行和取回

- U/EoH 按 [首页 CLI 命令](../README.md#预检启动查询和取回)预检、提交、查询、恢复、冻结后外评和导出。配置中 `research.runs` 选择种子，`research.budget` 和 `research.holdout` 保存研究口径，`execution.api` 和 `execution.slurm` 设置模型、并发和资源。模型或科研协议改动须先由研究人员决定。
- Ross-style 在本项目使用 `tools/prototype_hh.py`、`configurations/prototype-hh/{tsp,fjsp,obp}.json`。按[原型路由操作](传统状态路由基线.md)从拟比较的 U 协议绑定输入，再用 `check`、`train`、`status`、`evaluate`、`export`。旧断点与冠军的复核使用其原源码归档。
- Best Fixed H 用 `tools/experiment.py fixed-plan` 预检，按[固定 H 操作](R15真实验收与六组.md)评价或复用已核验成本。选择依据是训练成本，正式外评复用已选的 H。跨种子统计适用于独立搜索，固定 H 单列。

## 新版无 API 验收

在已解压的新版本根目录运行。使用独立目录中随包提供的 Mock 配置。以下命令供批准现场验收后使用。

```bash
P=$HOME/hdl-envs/portable-v2/bin/python
MOCK=configurations/experiments/slurm-no-api-smoke.json
"$P" -s -B tools/experiment.py prepare "$MOCK"
"$P" -s -B tools/experiment.py run "$MOCK" --approve
"$P" -s -B tools/experiment.py status "$MOCK"
"$P" -s -B tools/experiment.py export "$MOCK" --out "$HOME/r15-mock-results.zip"
```

这份配置用于单种子调度冒烟测试。是否实际接续，以作业和审核回执为准。三种子验收还需每个种子达标并各自导出结果。2026-11-21 核查时，`128C_02` 只有 `node15`，双节点探针需选有至少两个可分配节点的授权分区。跨节点互斥的通过证据为不同节点各自产生的 `permit-pass-*.json`。

新版三种子验收使用 [r15p5-site-no-api.json](../configurations/experiments/r15p5-site-no-api.json)。导入 D06 参照后，将上述 `MOCK` 换成该配置，导出时使用新的 ZIP 文件名。每个种子要达到 20 个成功返回，最多 24 个演化请求预留。检查 `status` 的 `outcome=scientific_complete`、三组导出和至少两段作业回执。

已有 D06 参照可按[部署步骤](R15真实验收与六组.md#部署和回退)校验后复制到新版。真实候选评价和账户吞吐分别按[验收与回退](../DECISIONS.md#验收与回退)验证。
