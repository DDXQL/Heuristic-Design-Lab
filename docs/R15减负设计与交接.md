## 一份配置对应一个实验批次

在一份 JSON 中选择问题、方法和种子。正式比较通常为一个问题和一种方法配种子 501、502、503。科研参数在 `research`，分区、CPU、时间窗和 API 参数在 `execution`。每次新实验用新的 `name`。`tools/experiment.py` 提供 `prepare`、`run`、`status`、`resume` 和 `export`。Slurm 为每个种子运行独立作业，提交后可以退出 SSH 或关闭 Mac。用 `status` 观察候选进度、训练 J、API 发送和审核作业。

每个种子独立保存检查点、种群、随机状态、请求记录、评价与结果。同名批次保留防重提交保护，种子保留写入锁。新 R15 正式批次的激活与结算锁位于各自的 `batch-gate/`。每个批次自行协调请求并发、发送间隔和 429 冷却。同批的实际 API 在途上限是种子数与配置并发的较小值。每种子同时最多一份生成请求，CPU 评价在种子内串行。跨批 API 负载相加，切换分区只影响 Slurm 排队和计算资源。相关实现见[统一入口](../tools/experiment.py)和[批内并发与限速](../experiments/triad/batch_admission.py)。

每种子目标是 1000 个成功返回的演化候选。按当前正式模板，空响应及截断按配置排除，正常返回后的语法错误、接口错误、重复和评价失败照计。初始化与 H 构建各自计数。每次物理发送、使用量未知和失败均保留证据。HTTP 520/522/524 若已明确结束，保留原槽记录并在硬上限内开新槽。明确未发送的临时故障可有限重试。账户鉴权失效、网络子进程未收尾、检查点或许可归属异常时保留阻断证据。旧 R13 的历史结果按 1000 次演化尝试口径保留。相关规则见[候选计数与容错](../experiments/triad/candidate_policy.py)。

接近 Slurm 时限时保存检查点。批次审核作业核对应用完成状态和剩余授权，再据此提交下一段或导出终态结果。正式模板的 12 小时单段、48 小时批次、最多 4 段及每种子 1100 次演化请求预留都是配置值。查看 `phase`、成功返回数和审核回执判断科研进度，Slurm `COMPLETED` 只表示当前作业退出成功。见[续跑判断](../experiments/triad/time_continuation.py)及[批次审核](../experiments/triad/campaign.py)。

## 结果汇总与未完成事项

从每批的 `experiment.py export` 取得一个 ZIP，保留导出时给出的 SHA-256。单种子曲线在 ZIP 内的 `successful-response-curve.csv` 与 `best-J-by-successful-response.svg`，冻结冠军在 `frozen_training_champion.json`。

在 Mac 的 R15 源码根目录对已取回的文件运行以下命令。输出为新建的 JSON，分批列出种子结果、排除原因、训练 J 均值和样本标准差。

```bash
python3 -s -B tools/r15_results.py "$HOME/tsp-u-results.zip" "$HOME/tsp-eoh-results.zip" \
  --out "$HOME/r15-tsp-training-summary.json"
```

汇总只纳入已导出且完成 1000 个成功返回候选、具有有效训练冠军的 501、502、503。单个批次的部分结果可核对，三个种子均符合条件才标为三种子结果齐全。训练外评价留到冻结冠军后执行。FJSP 既有结果先核对版本、种子和计数口径，再确定需补的正式 R15 种子。

OBP-EoH 的三个正式模板种子本地预检通过。OBP-U 三个种子只缺正式 H401 冻结 10H。已离线核查 H401 配置、train96、参照和程序绑定，原上限为 40 次生成及 7680 次含复核求解。待安排独占账户时段并获授权后，按原入口生成、冻结和绑定。[H401 操作](R15真实验收与六组.md#obp-h401)

传统非 LLM HH 由「论文研究方案总览页」接续「文献检索与精读」，确定主基线、预算与评价规格。工程接入以正式采用的规格为准。
