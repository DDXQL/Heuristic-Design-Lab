# Tier 2 A4：成员与静态权重联合随机搜索 V1

状态：**设计与合成验收；尚未抽取正式候选或运行A4实验。** 起点`bb3b3ee`，工作树`codex/h-usage-space`。版本`A4-Static-RS-grid20-Q60-R5-v1-20261024`。未来正式授权后另建唯一run、冻结完整计划和协议SHA，不覆盖任何旧结果。

## 1. 科研问题与主方法

在固定H0–H9上，用不依赖LLM的成员／权重联合搜索，在有限查询预算下能找到多好的**固定**策略？主方法只用一种：**均匀、无放回随机搜索（RS）**，评估后保留最佳。随机搜索通过有限目标查询优化best-so-far，不宣称连续优化、局部最优或全空间最优。

采用预定离散权重而非连续浮点抽样，原因是有限预算下容易复现、精确查重、与已有0.05步长网格对齐，并避免把近零支持变化或浮点近似合并引入新执行语义。权重分辨率固定，不根据中途成绩细化。

## 2. 精确策略空间：865个规范策略

- 10个单成员SELECT；45个不同无序成员对，每对19个内部权重：`alpha=k/20, k=1…19`。总数`10+45×19=865`。
- 规范成员顺序为原H编号`i<j`。**alpha是较小编号H_i的权重**，H_j原始权重严格用Python表达式`1.0-alpha`构造，其他八项为浮点0。alpha与H0/H1历史网格的方向一致。
- 单成员输出V1 SELECT，唯一成员选择分数1、其余0。双成员输出V1 MIX，经现有适配器进入冻结WEIGHTED_SUM内核。一次完整排程乃至所有实例中成员／权重都固定；U不读取七维状态，不改变算子。
- 整数权重声明端点`(20,0)/(0,20)`规范为对应单H；同一成员重复声明先合并整数tick，再规范为单H。这些不占新增策略。生成器只产生有序不同成员对与内部k，天然没有此类重复。
- `canonical()`只规范本协议的**整数声明**，不是任意LLM浮点向量转换器。禁止把近似浮点权重四舍五入后当作等价缓存，例如`1-.7`与字面量`.3`可能不同；不宣称重建后的规范向量与任意原始比例向量逐位等价。
- 主空间最小正权重0.05，属于预定搜索范围，**不是host的近零阈值**。不新增epsilon、不丢小正权重、不做top-2或clipping。若未来换连续空间，所有极小正项、下溢、NaN/Inf等仍由原host处理，须独立协议。
- 单成员沿原始H分数；双成员各自对当前全部合法动作独立min–max，常量列为0，再按原host归一化权重加权。成员同分、dominant和动作job/machine同分全部沿用原规则；不利用排序编号改变破同分。

规范ticket：0…9为单H；余下按`combinations(range(10),2)`字典序，每对k1…19。只对规范声明精确去重；不同声明即使在已见训练排程上行为相同，仍视为不同策略，禁止凭历史成绩／轨迹事后去重。

## 3. 候选产生与先验

每个搜索重复仅调用`random.Random(search_seed).sample(range(865),60)`。整个查询顺序在读取任何候选成绩之前封存，采样函数签名只接受空间大小、预算、搜索seed；没有缓存、Fitness、H排名或incumbent输入。评价反馈仅用于记录best-so-far，不用于生成后续候选；同Fitness保留最早查询者，不按H编号决定搜索冠军。

这是865个规范策略上的均匀先验，**不是SELECT/MIX各半**：单H总概率10/865，双H总概率855/865，每个成员对含19个等可能内部权重。应披露此空间测度，不伪称所有模式相同概率。60查询平均约0.694个单H，并不保证抽中H0或覆盖全部成员对。

不提供免费初始策略、已知成绩或H0/H1冠军。原单H排名、45对表、21点网格、B2冠军和Oracle只作外部参照／评价缓存，不能进入候选采样。原H编号本身带训练排名，但均匀ticket采样不按该排名偏置；整个H集合和空间设计已经历项目开发选择，不能称完全无研发先验或独立确认实验。

固定H0/H1的权重网格是另一个问题，不作为“10H联合搜索”的替代；本协议也不根据已知H0/H1结果调整抽样概率。

## 4. 推荐预算与重复

固定**60查询／重复，5个搜索seed：2026102601…2026102605**；求解seed始终501。Python环境固定仓库3.12.10，计划SHA记录实际票号序列。改变求解seed不算新增独立搜索重复。

|计账项|主预算／硬上限|
|---|---|
|预先生成规范候选|5×60＝300个；生成计划不查询成绩|
|逻辑候选查询槽位|每重复最多60，总计300；无效／重复／缓存命中均占一次查询|
|逻辑完整train21预留|每查询21项／42遍，总6300项／12600遍；失败不退款、不补员|
|新增物理评价|扣除认证缓存／同campaign复用后，仍最多6300项、12600遍|
|实际启动|逐实例持久化首解／复检标记，分别统计；不能把预留当完成数|
|API／模型请求|0；无Prompt、Tier 1、U演化或留出入口|
|重试／加时|0；单项失败完整Fitness=null，不自动加时|
|运行启动时间预算|首次run起6小时，持久化UTC期限；剩余不足650秒不再启动下一查询，保存partial，不重置期限|

60约为865空间的6.94%，在无放回抽样下预期覆盖33.69个、约34个不同成员对（精确解析值见本轮成本估计表），形成覆盖非等权比例的成员／权重基线，仍是有限预算搜索。5个重复为首轮可承担的随机性观察，不支持高统计功效或普遍优势结论；不为机械匹配旧19/20请求而选预算。

历史45对完整构造时间均值约36.99秒、中位34.53秒、范围8.65–81.43秒（两遍合计，非完整生命周期）。73个已核查规范策略可作为质量缓存候选；按均匀抽样解析期望，5重复中新增不同策略约239个，套用旧等权均值约2.5小时计算量，仅为**粗略场景估计**。新权重会改变路径和动作数，源文件扫描、进程与监控也另有开销，不能保证完成时间。

极端无缓存时6300项各等30秒的等待分配可达52.5小时，故另设6小时启动门槛。650秒包含21×30＋退出／清理余量；OS/I/O不承诺严格在第6小时瞬间结束，也不接受任何超过30秒的完整结果。触及运行启动期限即记录预算截断，不追加重复、不把部分重复当60槽位成绩。

## 5. 执行器与期限

复用独立Baseline-A Supplemental T30的完整接收收集器：首解、复检、该实例结果交付及末项after留证共享30秒；首次等待含子进程启动。不是每遍各30秒。全部结果收齐后另等最多2秒exit0，期间不接收迟到成绩；失败沿0.05秒join及terminate/kill清理。新A4worker只替换为规范常量policy，冻结V1／Fusion／H资产全部不改。

成功要求完整21实例、原LB/score、可行性、首解复检结构及物理排程一致、源码／加载身份前后一致、子进程policy/ticket/vector身份匹配、正常exit0及接收线程已停止。普通已认证T30超时只认证无效，可继续独立查询；任何未知进程／线程、源身份、非预期退出、复检不一致、缓存不完整或账本失配立即持久化Stop。

这与旧T15 poll/recv不同；也与旧B2的包装和初始化不同，历史结果不能直接组成同期墙钟公平比较。正式评价必须在新目录冻结源文件、H顺序、train21数据SHA／LB、全部300票号及协议SHA，运行中禁止修改或补抽。

## 6. 缓存与断点恢复

本轮只建立**73条元数据索引**，不由A4采样器查询它。包括10单H、45等权对、H0/H1网格新增的18个内部非等权点；端点和等权重复只算一个规范策略。索引不含Fitness，记录规范spec、原始文件SHA及证据等级。原始结果当然含成绩，但只有具体查询后由独立评价接口读取，不传给采样器。

每次候选查询先持久化逻辑预留，再查缓存；缓存命中也消耗一个槽和21/42逻辑预留。查证相同H代码／顺序、train21／LB、规范浮点向量、内核、原始结果SHA及完整两遍证据后，可复用**质量**。保留历史种子与进程认证缺口，不补造PID/exit0，不将历史耗时记成本次新增计算。

T15失败不能作为T30失败缓存；不能把原null改为完整成绩。本campaign内已认证T30超时可作为资源约束下的负缓存，后续查询仍占槽、不再重试，同样保持null。它不是策略普遍不可解的证明。跨重复共享缓存，因此重复表示独立搜索路径，**不是独立物理计时实验**。

缓存未命中时，先持久化21/42物理预留再创建worker。中断只恢复已认证completed条目并跳过；任何reserved、孤立证据、checksum或来源失配均停止，不能自动重复消费、重置seed、删除锁或扩大预算。结果、来源及过程文件摘要与checkpoint绑定。六小时期限跨进程恢复保留，不因重启重新计时。

## 7. 分析计划与公平性

逐重复输出60槽位best-so-far、最终质量、最佳规范策略、查询清单／计划SHA、合法率、完整有效率、超时率、重复率、缓存率、逻辑与物理预算、实际两遍启动、时间和资源。完整重复报告全部5个值及中位/IQR/范围；全无有效候选的重复保留null和失败重复计数，不将其静默剔除为成功重复。数值统计若只对非null有效冠军计算，须标注条件样本数及null计数。partial重复单列，不冒充完整预算结果。

对认证完整结果可计算逐实例Cmax/LB、对H0、最佳等权、最佳已测H0/H1静态网格和B2的ΔFitness与胜负平。平均归一化比率变化为`mean(Cmax/LB)_A / mean(Cmax/LB)_B - 1`；同时给Cmax总和，不能以总Cmax替代Fitness。

旧B1/B2只作训练内参考：B1已知19次请求／14个完整候选；B2是20次真实生成、19个完整评价及1次重复，另有21参考网格（16新＋5复用），其中5个P0不是额外再加5。API成本、解析／重复、初始化与缓存不同，不能追认为严格同生命周期A/B。

未来LLM-U／GP-U若比较搜索能力，须共同冻结查询槽位、物理预算、初始化、先验、失败／重复／缓存规则及执行器；额外列Token/API和真实计算，不把固定族构造合法率100%当作相同任务下生成质量优越。若研究墙钟效率，应另做同期统一环境并明确是否关闭历史缓存，不能凭本混合缓存批次结论代替。

“找到的静态策略质量”“在有限预算找到它的能力”“动态表达能力”分开：即使动态冠军超过A4，也可能是有限随机搜索遗漏、粗网格分辨率或搜索先验差异，不能直接归因状态控制。静态领先也不能证明所有动态U无价值。train21是已开发训练集，不使用已暴露test28或其他留出确认泛化。
