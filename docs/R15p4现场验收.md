# R15p4 现场验收

验收包使用运行器 `721e9ed`，集群根目录为 `$HOME/hdl-deploy/triad-candidate-runtime-20261120-r15p4`。它包含已保存的 D06 train20 参照。原 R13 作业在独立目录运行。验收使用批次自己的 Mock 账户目录，可与 R13 同时排队，所需 CPU 仍由 Slurm 分配。

## 无 API 集群验收

上传并解包 `r15p4-site-acceptance-20261121.zip` 后，在集群 Linux 终端运行。

```bash
P="$HOME/hdl-envs/portable-v2/bin/python"
S="$HOME/r15p4-site-20261121/site.py"
"$P" -s -B "$S" check
"$P" -s -B "$S" submit --approve-mock
"$P" -s -B "$S" status
```

`check` 校验并部署到独立目录，复核真实 TSP 配置的 D06 路径和 Mock 配置。`submit` 提交双节点文件锁探针，以及 TSP U 三个 Mock 种子 `901`、`902`、`903` 和它们的依赖审核作业。每个种子目标为 20 个 Mock 演化返回。30 分钟的 Slurm 时限配合 27 分钟收尾阈值与 10 秒 Mock 请求间隔，让验收可以观察到实际的分段提交和接续。每个种子各自留下账本、检查点和导出结果。`status` 读取实际 Slurm 作业和文件回执。三项同时通过时，`site_ready=true`。

- `two_node_permits_ok` 需要两个不同节点看到同一把许可锁，且双方都验证了互斥和释放后的重新取得。
- `dependency_and_reviews_ok` 需要已有作业与审核依赖对应，并出现下一段的作业与审核回执。
- `three_seed_mock_ok` 需要三条独立搜索全部达到 20、产生导出，至少一条经历暂停和接续，真实发送和实际求解均为 0。

## 真实 API 并发小试

待 R15p4 无 API 验收通过、R13 作业结束且同一 API 账户可独占后，按供应商或课题组确认的 RPM、TPM 和并发限制，逐档批准。三种子搜索每种子同一时刻最多一份请求。测 4 路和 8 路需使用独立的合成请求探针，档位和正式实验分开记录。

| 目标在途上限 | 每档请求硬上限 | 样本组织 |
| --- | ---: | --- |
| 2 | 4 | 两波，每波最多 2 次 |
| 4 | 8 | 两波，每波最多 4 次 |
| 8 | 16 | 两波，每波最多 8 次 |

三档合计最多 28 次物理发送，0 次求解，0 次自动补发。每档使用同一模型及 V5 非流式传输，固定短合成提示和输出上限。记录实际在途峰值、成功返回数、请求延迟和整档吞吐量、429 及网关错误、已知 token 和用量未知次数。记录供应商回传并可从客户端核实的限流字段。现有 V5 能提取 429 的 `Retry-After`。无可核实值时记录未知。遇 429、认证失败、未知在途或用量异常，停止升档。短小试可验证限定条件下的峰值和表现，无法据此确定账户长期上限。

并发小试和训练评价小试各自授权。后者拟采用独立的 TSP U/EoH 各一个初始化槽，合计最多 2 次物理发送、40 个候选–实例评价、80 次含复核求解。它检查真实生成、代码校验及训练评价接通情况。成功返回的演化计数及故障补槽已有 Mock 回归证据。真实小试的执行入口和账户许可另行确认。
