# 传统状态路由基线：选型、实现与运行边界

2026-11-23。本次选择并实现 Evolutionary Prototype Router（Ross-style adaptation），作为同一冻结 H 下与 LLM-U 比较的传统非 LLM 基线。开发树为 `Heuristic-Design-Lab-prototype-hh-20261123`，分支为 `codex/prototype-hh-20261123`，从 R15 开发提交 `2ac2670` 派生。本次没有启动真实训练、H/U 求解、留出评价、API 或 Slurm。正在推进的 OBP-U 及原六组的源码、运行和配置不变。

## 研究问题与方法身份

比较的问题是：在同一 H、同一可见状态、同一训练目标和构造规则下，传统进化搜索得到的状态路由，与 LLM 演化程序 U 的效果和成本有何差异。H 的构建是共同投入，另列成本。表示形式、初始化和优化算子也不同，效果差异不能全部归因于 LLM。

原始依据是 Ross、Marín-Blázquez、Schulenburg、Hart 的 GECCO 2003 论文 [Learning a Procedure That Can Solve Hard Bin-Packing Problems](https://doi.org/10.1007/3-540-45110-2_5)，[论文正文](https://www.cs.york.ac.uk/rts/docs/GECCO_2003/papers/2724/27241295.pdf)。§6.1 定义状态原型与关联启发式，§6.2 给出交叉变异，§6.4 给出稳态遗传引擎，§7 使用种群 40、500 轮和初始 16 个原型。原文用装箱专用状态、H 和抽样适应度；这里替换为方案 A v3、问题级冻结 H 和完整训练 J。原文新个体初评有 4／5 个问题的表述差异。本次不沿用该抽样机制，不能称完整原文复现。作者实现仍未核实；代码为依据原文独立实现的适配。

前期选型保留在主项目 `reports/traditional-routing-baseline-screening-20261117/REPORT_ZH.md`，来源为“文献检索与精读”。DDQN-H 仍为备选；其奖励、交互预算、网络和检查点选择未确定，本次未实现。没有增加其他 HH 方法或状态消融。

## 已实现的默认规格

下表记录本次选型实现的默认值，不把它们追溯表述为旧六组中已批准的设置。启动时冻结配置，恢复不得变更参数或预算。

| 项目 | 当前实现 |
| --- | --- |
| 状态与动作 | 方案 A v3 的 14 项共同信息及原允许辅助字段。14 项不是 14 维。只读当前状态，一步只选一个 H，H 执行动作；没有 MIX、H 预演或在线 LLM |
| 三问题 | 分别绑定各问题的冻结有序 10H，并分别训练；不声称同一个模型跨问题直接部署 |
| 训练输入 | 从一份真实 LLM-U 的 `Protocol.json` 及明确 SHA-256 导入嵌入的 H、完整训练实例、顺序和参照；核对共同状态、问题级构造器、调度／距离与 T30 依赖的源码哈希；不重新生成 H，不扫描历史运行 |
| 编码 | 计数 `x/(1+x)`；标准差乘 2；其余已归一化量保留原值。缺失值用 0 占位并拼可用性标志，真实 0 与不可用保持可区分。上一条 H 用 K+1 类独热编码，含 None |
| 距离 | 十个标量、四个逐 H 数组各一组，辅助字段一组，共 15 组；先取组内均方距离，再等权平均。同距离取更早原型。K=10 时编码长度为 114，不是改变共同状态定义 |
| 规模 | 种群 40；初始每个个体 16 个原型；允许 1—32 个原型 |
| 原型 | 一个实数中心与一个 H 标签；中心各坐标限制在 [-3,3]。中心可不对应真实状态，不能把它解释为额外统计样本 |
| 初始化与扰动 | 初始坐标 `N(0.5,0.25²)` 后限制到 [-3,3]；坐标扰动 `N(0,0.1²)` 后同样限制；H 标签均匀抽取。正态尺度和 32 上限是本项目适配默认 |
| 父代与子代 | 第一父代从两个不同个体锦标赛选取，第二父代均匀抽取，允许与第一父代相同；每轮生成两个子代，均基于这两个原父代。两个子代反馈后才更新种群 |
| 交叉 | 等概率使用保持字段位置的变长两点交叉，或每个完整原型以 10% 概率交换归属。两点交叉的两父代分别选块位置、共享字段偏移；涉及同块时共同排序偏移 |
| 变异 | 每子代 10% 概率触发；条件概率：加原型 25%、删原型 25%、坐标／标签变异 50%。后一种的每位概率为 `1/[4(d+1)]`，d 是编码长度；标签均匀重抽 |
| 边界 | 空交叉子代先换回对应父代再变异；最终原型数越界则退回对应父代副本。副本仍占子代槽，无隐藏重抽 |
| 适应度与生存 | 现有完整训练 J 最小化、T30 和双遍复核。无效候选 J=null，内部排序视为无穷；不以成功前缀求均值。父代加两个子代按 J、固定 ID 留 40 个 |
| 冠军 | 在初始化及全部后续完整有效候选中按训练 J、固定 ID 选择；不按验证或测试重新选择 |

计数压缩、组权重及高维距离可能影响原型的学习能力，目前没有效果证据。测试集不能用于调尺度、原型上限或算子。改变这些设置应建立新的训练身份。

## 预算与结果

每问题使用 501、502、503 三个独立搜索种子，共享同一问题的 H。每种子 40 个初始化槽，随后 500 轮、每轮 2 个子代，共 1040 个逻辑候选槽。这个规模参考原文搜索引擎；并非依据“1000 个子代与 1000 次 LLM 返回等成本”。初始化与演化分别报告。

重复、无效及评价失败均占槽，不补足有效候选。相同候选可在同一种子和同一冻结协议内复用已经结算的评价，包含已知失败；缓存命中仍计逻辑槽并标出来源，不增加真实求解。遗传引擎没有 EoH 的同分惩罚或有限父代门槛；这些不是本算法的机制。

若全部唯一有效且每例双遍完成，每种子最多启动 `2×1040×m` 个实例求解。m=21／20／96 时分别为 43,680／41,600／199,680；最终 m 以绑定的真实 U 协议为准。冻结后评价另计。不存在模型请求或 token 成本，但存在遗传计算、状态提取、距离计算和实际构造成本。

导出包括候选及最好训练 J 曲线 CSV、逐实例成本 CSV、成本 JSON、摘要和完成后的冻结模型。实例 CSV 中决策数与 H 调用数是每遍语义计数，CPU 与完整行时间包含首解和复检；成本表按已认证遍数汇总。失败／中断部分的未知 CPU 保留 null，不填 0。H 成本从源 U 协议保留；其未知项仍未知。

三种子汇总报告逐次训练冠军、均值和样本标准差。它不代替冻结后评价，也不覆盖重新构建 H 的变异。没有最终结果前不宣称传统 HH 或 LLM-U 更优。

## 用户手动执行步骤

以下命令从新工作树或包含本次实现的新发布根执行。`U_PROTOCOL` 必须替换为取回的、拟比较的真实 U 协议路径；不读取 U 冠军的测试成绩。模板缺绑定时预检给出 pending，不启动任何工作。

```bash
P=$HOME/Developer/cluster-deployment/mac-portability-env-v2/bin/python
"$P" -s -B tools/prototype_hh.py check configurations/prototype-hh/tsp.json

# 纯文件绑定：读取 U 的冻结训练输入并写一份新配置，不求解。
U_PROTOCOL=/替换为真实U目录/Protocol.json
"$P" -s -B tools/prototype_hh.py bind configurations/prototype-hh/tsp.json \
  --u-protocol "$U_PROTOCOL" --out configurations/prototype-hh/tsp.bound.json
"$P" -s -B tools/prototype_hh.py check configurations/prototype-hh/tsp.bound.json
```

FJSP／OBP 换对应模板及 U 协议。OBP 必须是当前预设 N 箱、向量 H、R_code、已交付状态和冻结 10H 的身份。TSP 训练直接复用 U 协议中的 LKH 值和路线，不计算 LKH。训练绑定不读取验证／测试实例。

先由用户手动做有限真实验收，确认共享求解器能在 T30 内完整评价原型模型，再继续同一个目录。下述第一条最多评价一个初始化候选，即最多 `2m` 次实例求解，不代表已验收通过。集群只在获分配的计算资源上运行；本工具不会调用 sbatch。当前评价为单候选、串行实例；不要默认沿用 OBP-EoH 的 4 路评价。另留一个控制核。

```bash
CFG=configurations/prototype-hh/tsp.bound.json
RUN=runs/prototype-hh/tsp-501
# 以下开始真实 CPU 训练求解，均由用户手动启动。
"$P" -s -B tools/prototype_hh.py train "$CFG" --seed 501 --run-dir "$RUN" \
  --execute --max-candidates 1
"$P" -s -B tools/prototype_hh.py train "$CFG" --seed 501 --run-dir "$RUN" \
  --resume --execute --max-seconds 36000
"$P" -s -B tools/prototype_hh.py status "$RUN"
"$P" -s -B tools/prototype_hh.py export "$RUN"
```

502／503 使用各自新目录与相应种子。`--max-candidates` 和 `--max-seconds` 只控制本段何时停止，均在候选之间生效，不改变累计预算；`max-seconds` 不是严格进程时限，须预留一个完整候选和退出时间。恢复保留 RNG、原父代及未评价的第二子代，不重开初始化。目录内创建 `PAUSE` 可请求候选完成后暂停；继续前由用户移除该文件。互斥文件不允许重复 writer；跨节点文件锁尚未现场验收。

进程若在评价中断开，保留 inflight 并拒绝自动重放，即使有 result.json 也需人工核查工作进程是否退出。摘要分别列出已结算候选、已占用槽和未结算槽，不把未知工作填成零。预算未完成时只输出中途最好；只有 completed 且至少一个有效候选才导出 `exports/frozen-model.json`。全无效仍消耗预算，结为 `completed_no_valid_candidate`。

```bash
"$P" -s -B tools/prototype_hh.py summarize \
  runs/prototype-hh/tsp-501 runs/prototype-hh/tsp-502 runs/prototype-hh/tsp-503
```

冻结后评价使用预先指定、含内容哈希的 validation／test manifest，单独新目录。TSP 需要该批留出实例自己的固定 D06 参照文件；不能用 train20 的 LKH 文件代替。评价前落盘模型／清单／参照身份，再调用原双遍评价，不选新冠军。程序拒绝训练内容混入留出清单，但无法据此证明没有其他历史暴露，论文需另行说明历史用途。

```bash
# 真实留出评价示例；路径必须由用户替换并预先确定。
"$P" -s -B tools/prototype_hh.py evaluate \
  --model runs/prototype-hh/tsp-501/exports/frozen-model.json \
  --manifest /替换为预指定留出集/manifest.json --split test \
  --reference /替换为该留出集自己的/D06-reference.json \
  --run-dir runs/prototype-hh/tsp-501-test --execute
```

FJSP／OBP 不传 `--reference`，按既有规则算评价端参照。工程合成模型带 `engineering_only=true`，不得进入真实留出评价。

三份留出评价目录用 `tools/prototype_hh.py summarize-evaluations DIR501 DIR502 DIR503` 汇总逐次 J、均值和样本标准差。三份必须对应同一预指定清单、参照和训练设置；任何一次评价失败时保留该行，均值／标准差为 null，不只平均成功种子。它不会按留出成绩重新选择模型。
